# 넓은 감사의 site_analysis 수정 보고

감사 원본 네 파일의 `site_analysis`가 들어 있는 표 행 37개를 모두 읽고 수정 전 코드와 대조했다. failure 11행, plan 6행, security 8행, env 12행이다. 아래 번호는 각 감사의 원래 번호이며 코드 위치는 이번 수정 후 파일 기준이다. 외부 웹과 공급자 문서는 접속하지 않았다. 표의 고침은 해당 코드 경로의 변경을 뜻하며 실제 웹, 과금, OS 권한의 실행 검증을 뜻하지 않는다.

수정은 이 폴더 안에서만 했다. 기존 FIX-REPORT, FIX2-REPORT, FIX3-REPORT와 RESUME-REPORT는 수정하지 않았다. `SITE_ANALYSIS_PROXY`, 부분 축 및 개별 가림 셀 보존, 미소비 유료 답 재생, 의미 합치기, 시간 초과 비용 추정, 실패 작업만 포기하는 원칙을 유지했다. 기존 실패 카운터는 국소 처리로 바뀌어 있었지만 관찰 오류 콜백에 남아 있던 전역 중단 설정은 이번에 제거했다. 실행 중인 다른 분석 프로세스와 그 체크포인트는 조작하지 않았다.

## 먼저 바꾼 경계

비용은 둘러보기, 축 분석, 가림과 합치기로 나눈다. `--browse-share` 기본 0.5, `--privacy-share` 기본 0.2, `--merge-share` 기본 0.1이며 축 분석은 나머지 0.2다. 세 인자의 합계는 Decimal로 검사한다. 모든 회차에 공통인 몫이며 다른 단계 몫으로 새 호출을 시작하지 않는다. 축 묶음의 75%까지 읽기와 교정을 허용하고 마지막 25%를 최종 답변에 남긴다. 최종 답변에도 묶음 한도를 적용한다. 전체 UTF-8 봉투와 스키마, 프롬프트를 포함한 추정액을 호출 전에 비교한다. 가림과 합치기 사용액도 장부에 저장하고 재개 때 복원한다.

이 비용 경계는 실제 과금의 강제 상한이 아니다. Codex CLI의 출력 및 추론 청구를 여기서 강제로 제한하는 계약은 확인되지 않았다. 출력 16,000토큰도 추정치다. 한 호출의 실제 비용이 예약 추정보다 커지면 다른 단계에 남길 전체 잔액도 줄 수 있다. 이를 숨기지 않고 `provider_hard_cost_limit=false`, 추정 설명과 `usd_estimated`를 남긴다. Claude에는 단계와 묶음의 실제 잔액을 CLI `--max-budget-usd`로 전달하지만 실제 강제 동작은 호출하지 않아 미확인이다. 따라서 유료 답의 공개를 모든 공급자 과금 상황에서 보장한다고 주장하지 않는다.

시간은 `--browse-seconds`, `--analysis-seconds`, 기존 `--privacy-seconds`, `--merge-seconds`로 분리했다. 미지정 단계는 각각 기존 `--max-seconds` 또는 budget.seconds를 사용한다. 기본 1,800초는 전체 한도가 아니라 각 단계 한도다. 둘러보기 시계가 소진돼도 분석과 가림은 새 시간 창을 받는다. 재개도 새 창을 받으며 누적 비용과 계측은 이월한다. 답을 못 받은 묶음은 미완료이고 정상 부분 답만 보존해 가림한다. 앞 묶음 또는 회차가 미완료여도 전체 비용 중단이 없으면 다른 독립 작업을 계속한다.

브라우저 route는 모든 요청에 원본 스킴, 호스트와 유효 포트 경계를 적용한다. WebSocket의 ws/wss는 대응하는 http/https 원본으로 비교한다. iframe, 스크립트, 이미지, fetch와 외부 실시간 연결을 차단하고 시도, 전송 여부와 사유를 기록한다. 모델의 stop과 사람 확인 중단도 route와 수신 콜백에 적용하며 열린 실시간 연결을 닫는다.

문맥 상태 자체가 크면 `context:state`와 `context:manifest` 참조로 바꾸어 읽게 한다. 초과 객체를 전송하지 않는다. 응답 원문은 응답당 기본 2,000,000바이트, 관찰 버퍼 전체 32,000,000바이트, WebSocket 보관 메시지 1,000개로 제한한다. HTTP는 청크로 읽고 내려받기는 파일 앞부분만 읽는다. Chromium 본문은 CDP 스트림으로 받고 DOM도 브라우저에서 길이를 제한한다. 모델 stdout/stderr는 임시 파일로 받으며 stdout을 기본 4,000,000바이트까지만 메모리에 읽는다. 생략한 원자료와 부분 스트림은 잘림과 못 얻은 사유를 남긴다. 이는 전체 프로세스 RSS 또는 브라우저 자체 메모리의 강제 상한은 아니다.

## 실행한 확인

실행 검증은 아래 py_compile과 --dry-run만 했다. 작업 디렉터리는 `defense/web-proxy-defense/`다. 읽기와 편집에는 PowerShell, rg와 apply_patch를 사용했고 git status만 읽었다. commit, push, stash, Docker, 브라우저 기동, 실제 원본 및 중계 접속, 실제 모델 호출, 의존성 설치와 별도 테스트 파일 생성은 하지 않았다.

```powershell
python -B -m py_compile site_analysis/__init__.py site_analysis/catalog.py site_analysis/model.py site_analysis/prompts.py site_analysis/record.py site_analysis/windows.py site_analysis/observer.py site_analysis/resume.py site_analysis/analyze.py
python -B -m site_analysis.analyze --origin-url http://example.invalid/ --out site_analysis/offline-wide-analysis.json --dry-run
python -B -m site_analysis.analyze --origin-url http://example.invalid/ --out site_analysis/offline-wide-config.json --runs 1 --browse-share 0.25 --privacy-share 0.25 --merge-share 0.15 --context-chars 80000 --max-seconds 1 --browse-seconds 2 --analysis-seconds 3 --privacy-seconds 4 --merge-seconds 5 --request-seconds 0.5 --body-bytes 1024 --retained-bytes 4096 --stream-messages 3 --model-output-bytes 8192 --checkpoint-root %TEMP%/site-analysis-wide-private --provider claude --model offline-claude --reset-failures --fresh --dry-run
python -B -m site_analysis.analyze --origin-url http://example.invalid/ --out site_analysis/offline-wide-analysis.json --browse-share 0.6 --privacy-share 0.3 --merge-share 0.1 --dry-run
python -B -m site_analysis.analyze --origin-url http://example.invalid/ --out site_analysis/offline-wide-analysis.json --analysis-seconds nan --dry-run
python -B -m site_analysis.analyze --origin-url http://example.invalid/ --out site_analysis/offline-wide-analysis.json --context-chars 2 --dry-run
```

정상 컴파일과 두 정상 dry-run은 도구가 보고한 종료 코드 0이었다. 마지막 세 명령은 비용 몫 합계, NaN 시간과 너무 작은 문맥 창의 ValueError로 거부됐으며 도구가 보고한 종료 코드는 1이었다. 이 확인에서는 거부 사유와 공급자 미호출을 확인했다.

dry-run은 로컬 응답 객체와 메모리 저장 및 파일 API 대체만 사용한다. 기존 51개 축의 형식과 부분 답, 읽기 창, 의미 합치기, 중단 후 가림 재개 및 유료 답의 재호출 방지를 확인했다. 이번에는 다음 경계를 더 확인했다.

- 분석 몫을 소진해도 가림과 합치기 호출은 각 몫으로 계속되며 예약 추정액이 잔액보다 크면 공급자를 호출하지 않는다. 스키마와 한국어 봉투 바이트도 추정에 포함된다.
- 둘러보기 시계가 만료돼도 분석과 가림이 동작한다. 분석 시계가 만료된 부분 묶음은 미완료이며 정상 축을 보존해 다음 창에서 완료된다.
- 같은 원본 iframe과 fetch는 통과하고 외부 호스트 및 다른 포트의 요청은 차단된다. stop 후 자동 요청과 외부 WebSocket도 차단된다. 문자열, 숫자와 null 확인 플래그를 실행하지 않는다.
- 끝나지 않는 메모리 HTTP 응답은 지정 바이트만 읽고 닫는다. 원문 총량, WebSocket 메시지 수와 CDP 스트림 보관량을 확인하고 부분 크기를 기록한다.
- 상태가 창보다 커도 실제 JSON 문맥은 한도 안이며 전체 상태와 목록은 참조로 남는다. 읽기 보관 한도를 넘는 원문을 추가하지 않는다.
- LOCALAPPDATA 없는 환경의 경로 계산과 같은 이름의 서로 다른 출력 및 대상 분리를 확인한다. 메모리 파일시스템에서 보관 한 파일 이동 후 중단하고 같은 계획을 재실행해 state를 마지막으로 옮긴다.
- Claude의 예시 JSON 봉투에서 실제 비용과 답을 파싱한다. 실제 CLI와 과금은 확인하지 않는다.

정상 dry-run 출력은 `wide_fix_check=passed`, `resume_check=passed`, `network_requests=0`, `model_calls=0`, `files_written=0`, `login_values_read=false`였다. 지정 출력 두 파일과 명시 비공개 저장 디렉터리가 생성되지 않은 것을 파일 존재 검사로 확인했다. py_compile은 이 폴더의 __pycache__에 컴파일 파일을 쓴다. 시작과 마지막 git status에서 범위 밖 기존 변경 목록은 같았다. 미추적 폴더였으므로 git diff로 변경 전후를 비교했다고 주장하지 않는다.

개발 중 dry-run은 예전 외부 자원 통과 기대값, 예전 공유 시계 기대값, HOME 정보까지 지운 환경 모의 검사 때문에 실패했다. 새 경계에 맞춰 기대값을 변경하고 LOCALAPPDATA만 제외하는 환경으로 고친 뒤 통과했다. 실제 실행의 성공으로 대체하지 않았다.

## 남은 제한

로그인 계정 관찰은 사용자 지정에 따라 미구현이다. 상태 변경 GET의 자동 요청까지 원본 불변을 증명하는 기능과 미지 비밀의 전송 전 비공개 모델 심사는 구현하지 않았다. URL 의미와 개인정보의 의미를 코드로 판정하는 규칙은 추가하지 않았다.

실제 Chromium CDP 지원, 프레임 이벤트 순서와 빠른 응답, CLI 인자 호환성, 공급자 청구, 소유자 DACL, OS 잠금 및 실제 디스크 보관 중단은 실행하지 않아 미검증이다. CDP 스트리밍 시작 전 이미 끝난 응답 또는 지원하지 않는 브라우저에서는 본문을 못 얻을 수 있다. DOM 화면 표본은 제한된 화면 텍스트이며 과거의 전체 접근성 스냅샷과 동일하지 않다. 제한을 넘은 원자료는 보관하지 않는다. 기존 큰 체크포인트의 초기 역직렬화와 브라우저 및 CLI 자체 메모리, 디스크 사용량의 강제 상한은 제공하지 않는다.

이전 버전의 실행 중 프로세스는 새 OS 잠금에 참여하지 않는다. 따라서 그 프로세스와 같은 출력의 새 병행 실행 보호를 보장하지 않는다. 이번 작업에서는 그런 병행 실행이나 저장 이관을 실행하지 않았다. 기존 실행 이후의 재개는 신원과 장부가 맞는 이전 폴더를 읽으며 새 저장 경로에 이어 기록한다.
