# 분석 기록 규격 1.1

입구는 `site_analysis.analyze`이며 결과는 UTF-8 JSON이다. `--out`의 명시 경로를 사용한다. 개인정보가 없는 결과도 커밋하지 않는 비공개 위치에 둔다. `--dry-run`은 결과 파일을 쓰지 않는다. 축 정본과 묶음 정책은 [axes.json](axes.json), 축 문서는 [AXES.md](AXES.md)다.

## 관찰과 전송 경계

모델은 다음 화면과 행동의 읽기 안전성을 판단한다. 로그아웃, 읽음 처리, 초대 수락, 구독 해지처럼 GET도 상태를 바꾸는 이동은 선택하지 않는다. 위험하거나 실행할 수 없는 후보는 이유를 다음 입력으로 돌려주고 탐색을 계속한다. 축 질문에 답할 관찰이 충분하거나 같은 종류의 페이지를 더 봐도 답이 실질적으로 달라지지 않는다고 모델이 판단하면 `stop`한다. 더 볼 안전한 관찰이 없거나 예산 또는 같은 실패 반복 상한에 도달해도 둘러보기를 끝낸다. 사람 확인 장치도 통과하지 않고 다른 후보를 고른다.

화면이 발생시키는 이미지, CSS, JS, 폰트와 API 중 원본과 스킴, 호스트, 유효 포트가 같은 GET/HEAD에는 별도 모델 심사를 하지 않는다. 외부 하위 요청과 iframe은 route에서 `external_request_not_sent`로 차단하며 WebSocket도 같은 경계를 적용한다. GET/HEAD 이외는 `보내지 않음(메서드)`로 차단한다. 차단 대상과 사유는 `requests`와 `unopened`에 남긴다. POST 읽기 API도 전송하지 않는다. 응답을 얻지 못한 자료를 없다고 판단하지 않는다. 요청 본문과 쿠키 및 인증 헤더 값은 기록하지 않는다.

폼 제출은 네이티브 메서드와 submit 이벤트를 가로챈다. `inspect_form`은 제출 이벤트를 발생시키지 않고 폼 대상, 메서드와 필드 이름을 읽는다. 이름 없는 필드도 남기며 값은 읽지 않는다. 과거 로그인 전송 예외는 삭제했다. `--login-env`는 정확한 자격 값 가림과 후속 계정 제거 인계에 쓰며 로그인이나 폼 제출 권한을 주지 않는다. 자격 입력 실패도 공개 관찰을 막지 않는다.

외부 최상위 화면과 모든 외부 의존 요청은 차단한다. 이 때문에 제3자 자원이 필수인 화면은 일부만 관찰할 수 있다. 해시 라우터와 JS가 구성한 주소는 브라우저가 실제 이동한 URL을 받는다. 공개 URL 칸도 개별 가림을 거치며 SHA-256 `route`는 남는다. URL의 원문 등장 여부로 이동을 제한하지 않는다.

새 창은 같은 문맥에서 관찰하며 `select_page`로 선택한다. 원본 경계 안의 WebSocket 서버 수신 프레임만 관찰하며 클라이언트 송신은 전달하지 않는다. 모델의 stop과 사람 확인 중단은 route와 수신 콜백에 적용하고 열린 연결을 닫는다. `read_only`와 `human_confirmation`은 불리언이어야 하며 형식 오류 후보는 실행하지 않는다. 서비스워커는 요청 가로채기를 우회하므로 차단한다.

## 예산과 표본

기본 실행별 요청 시도는 3,000회, 화면 이동은 60회다. 시간은 둘러보기 `--browse-seconds`, 축 분석 `--analysis-seconds`, 가림 `--privacy-seconds`, 합치기 `--merge-seconds`로 각각 설정한다. 미지정 값은 `--max-seconds` 또는 budget.seconds의 기본 1,800초를 사용한다. 따라서 기본 전체 시간은 1,800초 하나로 제한되지 않는다. 재개에는 새 단계 시간 창을 주고 누적 계측과 비용은 유지한다. 요청별 대기는 `--request-seconds`의 기본 30초와 둘러보기 잔여 시간 중 작은 값이다. 합친 답 가림 시간은 의미 비교 시간에서 제외한다. 기본 실행 수는 2다.

`sample_chars`와 `--context-chars`의 기본값은 각각 600,000자다. 모델별 적정값은 운영자가 설정한다. 정확한 토큰 수 추정이 아니다. 현재 URL, 열린 페이지, 방문한 실제 URL 전체와 횟수, 최근 피드백의 상태와 참조, 실행 예산과 비용 예산, 축 질문을 먼저 보존한다. 이 방문 목록은 모델 입력에만 있으며 기록에 추가하지 않는다. 피드백 상세와 교정 답은 참조로 보존하고 먼저 전달하며, 이어 최신 표본부터 창을 채운다. `sample_refs`는 전체 참조 목록, `omitted_sample_refs`는 전달하지 못한 표본 목록, `included_samples`는 전체 또는 표시된 부분 창이다. 응답과 요청 같은 자원 목록은 목록별 참조로 보존해 참조 목록만으로 창이 차는 일을 줄인다.

보관한 소스와 응답 원바이트는 `read_sample {ref,offset,limit,encoding}`으로 읽는다. 창은 바이트 또는 문자 단위와 JSON/base64 확장을 계산한다. 필수 상태와 참조 목록만으로 문맥 한도를 넘으면 `state_ref`와 `manifest_ref`로 보관하고 `state_exceeds_window`를 표시한다. 실제 전달 객체는 항상 문맥 한도 안이다. 참조조차 담을 수 없는 작은 창은 거부하며 CLI 최소 창은 1,024자다. 내부 교정 봉투가 한도를 넘으면 외부 호출 없이 상위의 창 처리로 돌려준다.

응답당 `--body-bytes` 기본 2,000,000바이트, 원문 버퍼 합계 `--retained-bytes` 기본 32,000,000바이트, WebSocket 보관 메시지 `--stream-messages` 기본 1,000개로 제한한다. Chromium 응답은 CDP `Network.streamResourceContent`로 수신하며 전체 `response.body()`를 읽지 않는다. DOM의 화면 텍스트와 HTML도 브라우저에서 길이를 제한한 뒤 전달한다. HTTP 본문은 작은 청크로 읽고 내려받기는 파일의 제한된 앞부분만 읽는다. 한도 이후 원자료는 보관하지 않으며 `capture_truncated`, `retained_size`, `capture_error`와 공개 `facts.capture`에 한계를 남긴다. 보관하지 않은 뒤쪽은 읽을 수 없고 부재 근거로 삼지 않는다. 읽기 원문과 읽은 창에도 각각 32,000,000바이트 및 1,000창 상한이 있다. 이는 Python 프로세스 전체 RSS 상한이 아니다. CDP가 지원되지 않으면 그 응답 본문은 못 얻음이며 무제한 읽기로 대체하지 않는다. 로딩이 끝났는데 받은 바이트가 0이면 전송 크기(`encodedDataLength`)가 응답당 한도 이하일 때만 `Network.getResponseBody`로 한 번 가져오고, 한도로 자른 뒤 `capture=cdp_response_body_after_finish`를 남긴다. 전송 크기가 한도를 넘으면 `error=body_not_fetched_over_limit`, 가져오기 실패는 `error=body_unavailable_after_finish:<종류>`, 초기 본문을 받기 전에 끝난 수집은 `error=initial_body_not_received`이며 모두 `completion_status=못 얻음`이다. 빈 본문을 성공으로 남기는 것은 스트림을 시작한 응답 중 전송 크기가 0이거나 알려지지 않은 응답뿐이다. 본문 항목은 응답 수신 이벤트에서 바로 만들므로 스트림 시작 전에 로딩 종료가 먼저 도착해도 그 응답을 놓치지 않는다. 같은 요청 ID의 새 응답이 그 항목을 바꾸면 이전 스트림의 결과와 실패는 새 항목에 반영하지 않는다. `Network.streamResourceContent`로 스트림을 시작하지 못한 응답(로딩이 이미 끝난 응답 등)은 실패 사유를 보관하고 같은 경로를 따른다. 로딩 종료 뒤 전송 크기가 응답당 한도 이하이면 `Network.getResponseBody`로 한 번 가져오며, 성공하면 `capture=cdp_response_body_after_finish`인 정상 본문이 된다. 가져온 본문이 없으면 전송 크기와 관계없이 그 본문은 `status=못 얻음`, `completion_status=못 얻음`이며 `error` 끝에 `stream_unavailable: <예외 종류>: <메시지 첫 줄>`을 `; `로 이어 붙인다. 앞선 오류가 없으면(전송 크기가 0이거나 알려지지 않은 경우 등) `error`는 `stream_unavailable: ...` 하나다. 로딩 종료 전에 둘러보기가 끝나면 `error=stream_closed_before_completion; stream_unavailable: ...`이다. 읽기 원문 사본이 한도에 닿으면 같은 대화의 오래된 사본과 그 창부터 비우고, 한도보다 큰 원문 하나는 비우기 전에 거부한다. 끝난 축 묶음은 원문 사본과 창의 본문을 비우되 창의 출처 기록(`requested_ref`, `offset`, `length`)은 남겨 근거 참조를 원래 관찰로 이을 수 있게 한다.

읽은 창은 둘러보기 세션, 축 분석 묶음, 의미 합치기 묶음과 개별 가림 작업 안에서 누적한다. `read_windows`에는 최신 창부터 `window_ref`, 원문 `ref`, 요청한 `requested_ref`, `offset`, `length`, `total`, `unit`, `encoding`과 잘림 여부를 남긴다. 실제 값은 최신 창부터 `included_samples`에 넣고 넘친 창도 참조로 남긴다. 읽을 때의 원문에는 고정 참조를 부여하므로 다음 호출에서 `provided-context`나 교정 입력이 바뀌어도 이전 범위를 다시 읽을 수 있다. 같은 원문, 범위와 인코딩을 성공적으로 다시 읽으면 기록 순서만 최신으로 갱신한다. 성공한 반복 읽기를 금지하지 않는다. 축 분석 묶음이 `_read_sample` 또는 `_find`를 목록으로 요청할 때 한 항목이 실패하면(범위 오류 `InvalidSampleRange`, 창 부족 `SampleWindowTooSmall`, 빈 찾기 문자열 `FindTextEmpty`는 `ValueError`, 알 수 없는 인코딩은 `LookupError` 등) 그 항목만 `read_errors`에 요청, 예외 종류(`error`)와 메시지(`detail`)로 남기고 목록의 나머지를 계속 처리한다. 다른 창의 결과, 찾기 결과, `not_read`와 알 수 없는 참조의 `read_errors`는 같은 피드백으로 전달된다. 실패한 항목이 있는 응답은 그 묶음의 같은 실패 반복 횟수에 첫 실패 항목의 오류 코드(없으면 예외 종류)로 한 번 센다. 같은 종류가 상한에 닿으면 그 응답 전체가 실패로 처리되고 그 묶음 분석이 멈춘다.

`--rates`는 `decoy_build`와 같은 형식, 즉 `budget.model_prices`, `model_prices` 또는 모델별 매핑을 받는다. 각 모델은 `base`와 선택적인 `long` 단가, `input`, `cached_input`, `output`, 선택적인 `long_input_threshold_tokens`를 가진다. `--max-cost-usd`가 파일의 상한보다 우선한다. 실제 실행에는 단가와 명시 비용 상한이 필요하다. 단가가 없는 dry-run은 실행 전 설정이 필요하다고 표시한다.

모든 모델 호출과 형식 교정 재시도에 같은 `cost_budget`을 전달한다. `max_cost_usd`, `spent_usd`, `remaining_usd`, `spent_by_stage_usd`, `remaining_stages`, `recent_average_call_usd_by_stage`가 있다. 단계별 금액은 사용 정보이며 배정액이나 별도 상한이 아니다. 남은 작업은 회차별 둘러보기, 미완료 축 묶음, 축 답과 사실 및 이동 판단의 가림 칸 수, 합치기와 합친 답 가림이다. 아직 둘러보는 회차는 칸 수가 늘 수 있음을 표시한다. 최근 평균은 단계별 비용이 기록된 마지막 최대 10회로 계산하며 호출이 없으면 null이다. 추정 비용이 포함됐는지도 표시한다.

비용 경계는 전체 누적 사용액이 `--max-cost-usd`에 도달했을 때 이후 호출을 멈추는 것이다. 단계 몫, 묶음 몫, 몫 비율에 따른 마지막 답 강제와 관련 CLI 인자는 없다. 추정액이 잔액보다 크다는 이유로 호출을 차단하지 않는다. 무엇을 읽고 언제 답할지는 모델이 남은 작업과 비용 정보를 보고 판단한다. 시간이나 비용으로 답을 못 받은 묶음은 complete가 아니며 정상 축과 읽기 창은 재개 때 보존한다. 같은 실패로 포기한 축만 terminal_axes로 구분한다.

전체 UTF-8 요청 봉투와 스키마, 프롬프트의 바이트 수를 입력 토큰 추정치로 삼고 출력 16,000토큰을 추정한다. 이 추정은 시간 초과와 강제 종료 호출의 비용 기록에 사용하며 `usd_estimated`를 남긴다. Codex 사용량과 Claude의 `total_cost_usd`로 실제 비용을 정산한다. 한 호출이 남은 금액을 넘을 수 있으며 `provider_hard_cost_limit=false`다. Claude CLI에는 전체 잔액만 `--max-budget-usd`로 전달한다. 모델 stdout/stderr는 임시 파일로 받고 stdout은 `--model-output-bytes` 기본 4,000,000바이트까지만 메모리로 읽는다.

모든 호출의 비용 정보와 교정 피드백을 갱신한 뒤 보관한 원자료 참조로 문맥을 다시 구성하여 창 크기를 지킨다. 상태가 창보다 크면 읽기 참조로 전달하되 `cost_budget`은 직접 남긴다.

`--same-failure-limit`의 기본값은 8이다. 같은 도구와 인자 또는 같은 축에서 같은 오류가 반복된 횟수만 센다. 성공은 해당 작업의 실패 수를 지우며 정상 반복을 제한하지 않는다. 서로 다른 후보의 실패를 합산하지 않는다. 상한과 각 실패의 해시 및 횟수는 장부에 남는다.

## 기록의 주요 키

| 키 | 내용 |
| --- | --- |
| `schema_version` | `site-analysis/1.1` |
| `target` | 운영자 입력 URL의 SHA-256 |
| `catalog_version`, `catalog_sha256` | 사용한 축 정본 |
| `runs` | 독립 브라우저 문맥 또는 HTTP 쿠키 저장소의 실행별 기록 |
| `merged` | 익명 회차가 2개 이상일 때 그 권한의 합친 결과(`merged_by_authority.anonymous`와 같은 객체), 아니면 `null` |
| `merged_by_authority` | 권한(`anonymous`, `session`)마다 같은 권한 회차끼리만 합친 결과. 축마다 회차 원답, 묶음 정책에 따른 처리 표시, 모델이 합친 답(`combined_answer`)이 있고, 합친 답의 `findings`는 사실마다 `finding`, `label`(`both-runs`, `single-run`, `contradictory`), `runs`, `refs`를 담는다. 그 권한 회차가 하나뿐이면 그 회차 기록이 들어간다 |
| `consumer_guidance` | 원답, 비교, 합친 답과 관찰 한계를 모델이 함께 판단하도록 안내 |
| `model_calls` | 호출 목적, 모델, 상태, 토큰, 비용, 경과 시간과 실패 코드. 원시 대화와 제공자 오류 원문(`provider_stderr`)은 없다. 오류 원문은 비공개 장부에만 있다. 출력 없이 DLL 초기화 실패나 DLL 없음(0xC0000142, 0xC0000135)으로 끝난 호출은 `error=provider_start_failed`, 비용 0이며 연속 8회면 실행을 멈춘다. 그 밖의 사용량 미상 호출은 추정 비용(`usd_estimated=true`)으로 남는다 |
| `metrics` | 총 달러 사용량과 상한, 사용량 미확인 여부, 경과 시간과 반복 실패 장부 |
| `response_times` | 응답별 시각 측정, 출처와 측정 지점. 평균이나 보정 없음 |
| `copy_supplement` | `--copy-supplement`로 제공한 ready 복사 JSON의 서비스, 이미지 ID, 컨테이너 ID 해시와 시작 시각. 가림 후 공개하며 환경 값과 실행 인자는 가져오지 않음 |
| `removal_handoff` | 분석 자격 환경변수 이름과 복사 계정 제거 인계. 자격 값 없음 |
| `stop_reason`, `limitations` | 멈춘 사유와 못 얻은 범위 |
| `run_errors`, `merge_error`, `resume_pending`, `copy_resume_pending` | 조건부. 회차 실행 예외(내부 오류 코드가 있으면 그 코드, 없으면 예외 종류), 합치기 단계 예외, 이어서 실행할 남은 단계, 복사 보충 가림 미완 |

실행별로 `authority`, `facts`, `axes`, `decision_events`, `browse_stop_reason`, `model_decisions`, `group_errors`, `privacy`, `response_times`를 남긴다. `facts`에는 상태 코드, 헤더, 쿠키 이름과 속성, 경로 참조, 실제 화면 URL의 가림 결과, 요청 전송 여부와 사유, 폼 메타데이터, WebSocket 연결과 수신 수 및 차단 송신 수, 예산과 반복 실패 수가 있다. 본문 원문과 실시간 프레임 원문은 저장하지 않는다.

`model_calls[].cost_budget`과 `metrics.cost_budget`에 공통 비용 정보를 남긴다. `metrics.browse_cost_usd`, `analysis_cost_usd`, `privacy_cost_usd`, `merge_cost_usd`는 단계별 실제 또는 추정 사용액이다. 읽은 창, 고정 원문 참조와 가림 전 부분 답은 저장소 밖 비공개 체크포인트에 보존한다. 과거 장부에 있는 몫 필드는 새 실행의 비용 판단에 사용하지 않는다.

`decision_events`는 가림 모델 호출 없이 결정 직후와 실행 결과 후에 저장한다. `index`는 별도 `model_decisions`와 연결하는 0부터 시작하는 번호다. 도구 이름은 실행기가 제공하는 이름 또는 `unknown`, `target_route`는 대상 URL의 SHA-256이며 단일 경로가 없는 읽기와 `stop`에는 null이다. `status`는 `pending`, `completed`, `rejected`, `failed`, `not_sent` 중 하나다. 중단으로 결과를 아직 확인하지 못하면 `pending`이 남는다. `completed`는 도구 실행 완료이며 성공 HTTP 상태를 보증하지 않는다. `reason_present`는 이유가 비어 있지 않은지 나타내는 불리언이다. 인자, selector, 실제 URL, 이유 원문과 응답 원문은 이 장부에 쓰지 않는다. `model_decisions`에는 기존대로 모델 가림을 통과한 전체 결정만 넣는다. `metrics.browse_cost_usd`에는 이동 호출 사용액을 남긴다.

브라우저 계측 칸은 `{source,status,value,error}`이며 실패는 `못 얻음`이다. 사실 문자열을 모델이 교정한 경우 `privacy.corrected_fields`의 ID, 경로와 `source=model_privacy`를 함께 읽는다. 원래 계측 출처와 모델의 교정 출처를 구분한다. 상세 오류는 모델 입력에만 두고 영구 기록에는 오류 종류를 쓴다. 쿠키 파서 실패는 그 헤더의 쿠키만 `못 얻음`으로 남긴다. `browser_cookies`에는 브라우저가 보유한 해당 URL의 쿠키 이름과 속성을 별도로 담아 파서 실패와 독립적으로 관찰한다. 값은 포함하지 않는다. 쿠키 속성은 이름과 값의 배열이므로 임의 원본 키가 가림 후보에서 빠지지 않는다. 인증 도전 헤더는 모델이 기술 형태를 해석할 수 있지만 민감 값은 개별 가림에서 제외한다.

HTTP 대체 관찰도 GET만 보내며 일반 환경 프록시를 사용한다. 자동 리다이렉트 대신 받은 헤더를 모델에게 주어 다음 이동을 정한다. 화면, 클릭과 폼 검사는 제공하지 않는다. 본문 읽기 실패 시 받은 바이트와 완료 실패를 함께 모델에게 주며 다른 응답 계측은 보존한다.

## 축과 개별 가림

축의 상태는 계획의 `관찰됨`, `없음`, `사례 부족`, `못 봄`이다. 축마다 `description`, `evidence`, `confidence`가 있고, 확신 척도와 추가 설명은 모델이 정한다. 코드가 0에서 1 범위를 강제하지 않는다. 답이 빠진 축만 다시 묻는다. 코드는 답의 모양을 검사해 거부하지 않으며 모델이 붙인 다른 키도 보존한다. `final:false`는 더 읽으면 바뀔 수 있는 잠정 답 표시이며 받는 쪽은 이를 확정 근거로 쓰지 않는다. 여전히 얻지 못한 축은 `status=못 봄`, `description=못 얻음: 사유`, `source=analysis_runner`다.

가림 모델은 칸 ID마다 안전 여부와 교정본을 반환한다. 사실 문자열, 축 답, 이동 판단, 합친 답을 각각 검토한다. 미등록 ID는 사용하지 않는다. 한 칸의 실패로 다른 칸을 비우지 않는다. 묶음의 가림 응답이 불완전하면 실패 칸들을 나누어 교정한다. 공개할 수 없는 사실은 그 문자열만 `null`, 축은 그 축만 `못 봄`이며 `privacy.errors`와 `withheld_fields`의 ID, 경로, 이유로 연결한다. 이미 안전하게 공개한 칸은 다음 실패에도 남는다. 가림 결정마다 그 칸 입력의 해시를 비공개 상태에 남긴다. 입력이 바뀐 칸과 해시가 없는 이전 결정은 다시 검토한다. 가림 묶음은 문맥의 1/4 크기로 나눈다. 개인정보의 의미를 코드의 정규식으로 탐지하지 않는다. 모델 가림의 실제 정확성은 실행 검증 전이다.

관찰 시작 전과 각 결정 전후에는 민감 문자열을 비운 사실 장부와 결정 메타데이터를 저장한다. 관찰 종료 뒤에는 분석 묶음과 가림 처리 단위로 원자적 저장을 갱신한다. 중단 시 점검을 마친 칸과 숫자 계측이 남는다. 원시 진단은 터미널에도 출력하지 않는다. 모델 입력과 공개 교정본에서 운영자 자격의 정확한 문자열도 치환한다.

## 비공개 저장과 재개

모든 요청 회차의 축 분석과 축 답 가림을 먼저 진행한 뒤 사실 칸과 이동 판단을 가림한다. 이 순서에는 비용 배정이 없다. 사실 공개를 위한 두 번째 처리에서는 미완료 축 분석을 재호출하지 않는다. 지불한 사실 또는 이동 판단의 가림 답은 대상 scope로 재생하며 새 하위 우선순위 호출은 뒤로 미룬다.

단가와 장부가 있는 dry-run은 `resumed_cost_budget`, `saved_group_resume_check`에 전체 잔액, 단계별 사용 정보, 남은 작업과 저장 묶음의 로컬 대체 응답 재생 결과를 표시한다. 이 결과의 완료 표식과 소액 비용은 제어 흐름 확인용이며 실제 축 답이나 청구액이 아니다. 실제 저장, 원본 접속과 모델 호출은 하지 않는다.

저장 폴더 이름은 출력 파일 이름에 출력 절대 경로와 원본 URL의 해시를 붙인다. 기본 상위 위치는 LOCALAPPDATA, macOS의 사용자 Library/Application Support, 그 밖의 사용자 .local/state이며 `--checkpoint-root`로 절대 경로를 지정할 수 있다. 저장소 내부 경로는 거부한다. 기존 이름만 사용한 폴더의 신원이 일치하면 원본 파일을 바꾸지 않고 새 폴더로 읽어 이어간다. 이전 버전의 실행 중 프로세스는 새 잠금에 참여하지 않으므로 같은 출력의 병행 재개를 보호할 수 없다.

`state.json`에는 기존 자료형 태그 규격으로 관찰, 보관한 원바이트와 문맥, 부분 답, 가림 셀과 완료 표식을 저장한다. `ledger.json`에는 네 단계의 사용액과 모든 호출, 미소비 답을 남긴다. `run.lock`의 OS 잠금을 실행 전체에 유지하며 고유 이름 임시 파일을 fsync 후 교체한다. POSIX의 0700/0600과 Windows 소유 사용자 DACL을 적용한다. 보관 파일 목록을 archive-progress.json에 먼저 저장하고 state를 마지막으로 이동하여 중단된 보관을 다음 시작에서 마친다. 저장 실패는 전체 실행을 멈춘다.

같은 정규화 원본 URL, 축 정본 전체와 출력 절대 경로의 해시가 일치하면 완료한 회차, 관찰, 묶음과 셀을 건너뛴다. 미완료 묶음의 정상 축과 읽기 창도 복원한다. 완료한 의미 비교는 합친 답 가림이 중단돼도 다시 호출하지 않는다. 원본이나 축 또는 출력 경로가 다르거나 `--fresh`이면 이전 JSON을 `archive-<시각>/`으로 보존하고 새 비용 장부를 시작한다. 이전 버전의 묶음 답 파일만으로는 관찰과 비용을 복원할 수 없어 자동 재개하지 않는다.

재개 시 네 단계 누적 비용과 상한을 복원한다. `--max-cost-usd` 명시 시 사용액을 유지한 채 새 상한을 사용한다. 미소비 답은 재호출 없이 반환하며 단계 저장 후 소비 확인 번호를 남긴다. 실패 카운터도 복원하되 `--reset-failures`로 비용과 정상 답을 유지한 채 실패만 해제할 수 있다. 가림 모델이 공개를 거부한 셀은 이 옵션으로 해제하지 않는다.

운영자 준비 세션 회차는 둘러보기를 시작할 때 세션 파일에 쿠키가 있고 그 쿠키가 모두 만료됐으며 로컬 저장소 원본이 없으면 브라우저 문맥을 만들기 전에 그 회차만 멈춘다. 이 중단은 회차 단위다. 익명 HTTP 대체 관찰로 넘어가지 않고 그 회차의 분석, 가림과 합치기 모델 호출도 하지 않는다. 비공개 상태의 그 회차에는 `stop_reason=operator_session_expired`, 공개 기록의 그 회차에는 `browse_stop_reason=operator_session_expired`, `run_errors`에는 `error=operator_session_expired`가 남는다. 다른 회차는 계속 진행한다. 운영자가 세션을 다시 준비한 뒤 같은 명령을 실행하면 그 회차는 둘러보기부터 이어서 진행한다. 이때 준비 세션의 해시가 바뀌어도 세션 회차가 아직 시작하지 않았거나 아무것도 관찰하지 않고 만료로 멈춘 회차뿐이면 재개를 거부하지 않는다. 이전 세션으로 관찰한 세션 회차가 있으면 기존대로 `--fresh`가 필요하다.

미완료 둘러보기의 자료는 보존하지만 브라우저 프로세스와 쿠키 저장소는 직렬화하지 않는다. 브라우저는 마지막 화면을 다시 열고, HTTP 경로는 기존 표본과 현재 URL에서 이어서 판단한다. 완료한 둘러보기는 브라우저와 HTTP를 실행하지 않는다. `--dry-run`은 체크포인트를 읽기만 하며 `checkpoint_folder`, `resume_reason`, `resume_from`, `saved_cost`와 별도 시간 설정을 출력한다. 실제 저장, 원본 접속과 모델 호출은 하지 않는다.

## 두 실행의 합치기

두 실행의 가림 완료 답을 묶음별로 모델에게 보낸다. 모델은 축마다 `agreement`와 합친 `answer`를 반환한다. `answer` 옆에 둔 다른 키(findings 등)는 합친 답 안에 보존한다. 축 행의 형식 위반은 세 가지다. 축 행이나 `answer`가 JSON 객체가 아니면(문자열 등) `merge_answer_not_object`, 객체 행에 `answer` 키가 없으면 `merge_answer_missing`, `agreement`가 JSON 불리언이 아니면(문자열 `"true"` 등) `merge_agreement_not_boolean`이다. 응답에 축 행이 아예 없으면 예외 종류(`KeyError`)로 알린다. 코드는 그 값을 감싸거나 바꾸지 않고, 피드백의 `row_errors`에 축 ID별 오류와 기대 형식을 담아 그 축을 다시 묻는다. 읽기 요청과 함께 보낸 축의 형식 위반도 `row_errors`로 알리며, 이때는 반복 횟수에 세지 않는다. 같은 축의 같은 위반이 같은 실패 반복 상한에 닿으면 그 축에 `merge_error`가 남는다. 이 규칙이 생기기 전에 저장한 체크포인트에서 이미 받아 둔 행은 재개 때 다시 묻지 않고 저장된 그대로 쓴다. 의미 비교 또는 가림을 못 얻으면 해당 축에 `merge_error`를 남긴다. 코드가 문자열 동등성을 의미 일치로 바꾸지 않는다.

| 정책 | 묶음 | 코드가 하는 일 |
| --- | --- | --- |
| `union` | `identity`, `stop` | 모든 회차 원답을 보존하고 모델이 합친 답을 대표 답으로 둔다(`disposition=union_of_runs`). 비교 실패도 원답의 발견을 지우지 않는다 |
| `consensus` | `content`, `access` | 모델이 의미 일치(`agreement=true`)를 확인한 축만 합친 답을 대표 답으로 둔다. 아니면 대표 답은 `null`(`withheld_no_consensus`)이고 원답은 남는다 |
| `retain` | `appearance`, `runtime`, `generic` | 실행별 답을 보존하고 모델이 합친 답을 대표 답으로 둔다 |

코드는 원답의 상태 낱말(`관찰됨` 등)을 읽어 대표 답을 고르지 않는다. 대표 답은 언제나 모델이 합친 답이다.

`merged.axes`에는 `agreement`(미비교는 null), `disagreement`, `answers`, 모델이 합친 `answer`, `run_indices`, `disposition`, `comparison_source`, `merge_error`가 있다. `--runs 1`은 메움 합의를 만들지 않는다. 받는 모델은 원답과 근거, 합친 답 및 관찰 한계를 검토하며 묶음 정책을 적용한다. 합친 자유 서술만 읽으라는 고정 지시는 없다. 받는 `decoy_build` 코드는 이번 작업에서 수정하지 않았다.

`--provider codex|claude`로 공급자를 명시하며 기본은 Codex다. 두 CLI 모두 도구와 MCP를 끈다. Claude에는 전체 잔액을 --max-budget-usd로 전달하고 실제 modelUsage 식별자를 기록한다. CLI 인자와 실제 청구 한도는 이번 작업에서 실행 확인하지 않았다. 응답 스키마는 안내이며 유효 부분 답을 보존한다. 알려진 운영자 자격은 원문, URL 인코딩, JSON 유니코드 이스케이프와 base64 표현도 치환한다. 알려지지 않은 비밀의 모델 전송 방지는 구현돼 있지 않으며 공개 가림과 다른 문제다.

정상 및 dry-run은 종료 코드 0, 부분 실패와 상한 중단은 2, 사용자 중단은 130이다. 기록 파일의 저장 실패와 잘못된 실행 설정은 전체 오류가 될 수 있다. 이는 웹 내용의 의미 판단이 아니라 실행 의존성이다.
