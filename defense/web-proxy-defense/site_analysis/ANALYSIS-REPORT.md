# 1단계 분석 구현 보고

작성일: 2026-10-09. 이번 회차는 코드 작성, `py_compile`, `--dry-run`까지다. 원본 웹에 접속하거나 모델을 호출하지 않았다. 수정과 새 파일 작성은 `defense/web-proxy-defense/site_analysis/` 안에서만 했다. `decoy_build/`, 보류된 설치기, 기존 사용자 변경은 수정하지 않았고 commit, push, stash도 하지 않았다.

| 10, 11절 7단계 준비 | 독립 브라우저 문맥으로 두 번 실행하고 축 파일의 묶음 이름으로 합친다. `identity`, `stop`은 한 번의 발견도 보존하며 불일치를 표시하고 `content`, `access`는 일치한 답만 선택한다. 실제 웹의 일치율을 재지는 않았다 |
| 5.3, 11절 6단계 | 주소 모양으로 개수와 식별자 체계를 알아보는 코드는 넣지 않았다. 계획대로 비교 측정 전에는 모델이 본다 |
| 11절 8단계, 12, 13 | 웹 비교, 부재 상태의 정확성, 비용 실측과 방식 채택 판정은 수행하지 않았다. 합치기 적용 범위도 측정 전 구현 정책이다 |

다르게 정한 곳은 다음과 같다.

- 합치기에 쓸 `stop` 묶음을 축 파일에 따로 두었다. 사람 확인 장치 질문은 원래의 세 번째 묶음 `access` 호출에 그대로 들어간다. 제거 축 `identity` 전체에는 합집합을 적용한다. 축 답의 내용으로 합치기 규칙을 정하지 않는다.
- 일치 여부는 상태와 서술의 정확한 문자열 동등성이다. 의미가 같은 다른 표현도 불일치이므로 메움 근거가 적게 선택될 수 있다. 근거 참조와 확신 값은 실행마다 달라도 일치 판정에서 제외한다.
- 브라우저가 없거나 첫 브라우저 기동이 실패하면 HTTP 원문만 읽는다. 자동 리다이렉트, HTML 링크 추출, 로그인 대체와 폼 제출을 하지 않는다. 화면과 SPA 기능은 못 얻었다고 적는다.
- 폼 차단과 읽기 원칙 사이에서 로그인에만 예외를 뒀다. 환경변수 이름으로 받은 운영자 계정에 대해 모델이 드러난 정확한 인증 대상과 메서드를 고른 경우 한 건만 허용한다. 로그인 요청 전송을 인증 성공으로 간주하지 않는다.
- 웹소켓은 연결을 차단하고 시도 위치만 기록한다. 실시간 내용을 지어내지 않는다. 내려받기 파일도 저장하지 않고 못 얻은 경로와 사유를 남긴다.
- 원본 URL과 화면 원문은 기록에 넣지 않는다. 대상과 경로는 SHA-256 참조다. 임의 헤더, 쿠키 속성, 호스트, 폼 필드 이름은 모델이 허용한 문자열만 받은 그대로 적고, 모델의 자유 서술은 별도 원본 값 점검을 통과한 경우에만 기록한다. 가림 점검도 모델 판단이므로 실제 원본에서 누락 여부를 확인해야 한다.
- 요청 예산에는 전송 전 차단한 요청 시도도 센다. 쪽 예산은 화면 이동 시도를 센다. 관찰 시간에는 탐색과 요청 판단 모델을 기다린 시간도 포함된다. 예산이 소진돼도 이미 얻은 자료의 묶음 분석은 계속한다. 기본 숫자는 조절 가능한 출발값이며 실측값이 아니다.

| 요청 수, 쪽 수, 시간, 응답 시간 차, 사용 토큰 수, 일치와 불일치 수 계산 | 숫자 계산 |
| 두 답의 상태와 서술 문자열 비교 | 우리가 기록한 값의 동등성 대조. 의미 해석 없음 |

웹 의미를 알아보는 정규식, 키워드 분류, 태그별 해석, 특정 제품이나 DB 및 국가 형식 분기는 넣지 않았다. HTML 폼 제출은 브라우저의 네이티브 API를 가로채는 구조이며 폼의 목적은 모델이 판단한다. 표준 HTTP 헤더와 쿠키 파서는 수신 프로토콜 처리를 위해 사용한다.

## 받는 쪽과의 연결

`build.py`는 `--analysis` 파일을 JSON으로 읽어 `Runner`에 넘긴다. `Runner.context()`는 분석 전체를 `analysis`에 넣고 미끼 생성 AI와 검증 AI의 호출 문맥에 포함한다. 미끼 생성 AI가 `generate`를 요청하면 검증 AI가 선택한 모양을 검토한 뒤 메움 생성 모델은 `shape`와 `count`만 받는다. 분석 전체나 원문을 저가 모델에 직접 넘기지 않는다.

현재 받는 코드에는 고정된 분석 JSON 스키마가 없다. 이 결과는 `--analysis`로 바로 읽을 수 있지만, `merged` 선택과 `consumer_guidance` 준수는 받는 모델의 몫이다. 받는 쪽의 키 검사나 정책 강제는 이번 회차에 추가하지 않았다. 시간은 기존 메움 보고서의 `response_times` 키와 함께 내되 브라우저 측정 지점은 기존 보고서의 `relay_loopback_host`와 다르다. 현재 `runner.py`에는 시간을 자동 대조하는 고정 분기가 없다. 경로 원문이 없는 한계도 규격에 적었다.

## 실행 방법

작업 디렉터리는 저장소의 `defense/web-proxy-defense/`다. `--out`은 저장소 루트 `.tmp/` 아래의 경로만 허용한다. 실제 실행에는 로그인된 codex CLI가 필요하며, 화면 관찰에는 사용 가능한 Playwright와 Chromium이 필요하다. 이번 회차에 의존성을 설치하지 않았다.

검토용 오프라인 입구는 다음과 같다. `example.invalid`는 접속하지 않는 dry-run 입력이며 시험 대상의 주소가 아니다.

```powershell
python -B -m site_analysis.analyze --origin-url https://example.invalid/ --out ../../.tmp/site-analysis/offline-analysis.json --runs 2 --dry-run
```

`--budget`은 `requests`, `pages`, `seconds`, `sample_chars`를 받는 JSON 문자열이다. 지정하지 않은 키는 기본값을 쓴다. 예산은 실행별로 새로 센다. `--model`은 기본 `gpt-6-sol`을 바꾸고 `--model-timeout`은 호출별 시간 한계를 바꾼다.

`--login-env`에는 일반 사용자 자격의 JSON 객체를 담은 환경변수 이름만 준다. JSON 키 이름은 운영자가 정하며 모델에는 그 키 이름만 보여 준다. 실제 값은 브라우저 입력과 정확한 값 치환에만 사용하며 메모리에서 처리한다. dry-run은 해당 환경변수 값을 읽지 않는다. 분석이 끝나면 운영자는 그 계정을 폐기하고 복사된 계정도 제거 단계에서 지워야 한다.

생성된 결과를 받는 쪽에 넘기는 입구 형태는 `python -B -m decoy_build.build --decoy wordpress --analysis ../../.tmp/site-analysis/wordpress-analysis.json`이다. 실제 빌드에는 받는 쪽의 단가와 비용 상한 등 추가 인자가 필요하다. 이 명령은 이번 회차에 실행하지 않았다.

Python은 로컬에서 확인한 `3.13.14`다.

dry-run의 합치기 검사는 원본 관찰을 흉내 낸 결과 파일을 만들지 않는다. 내부 검사값으로 한 번의 발견 보존, 불일치 표시, 메움 불일치 보류 및 일치 답 선택, 검증 답의 실행별 보존을 확인한다. 원본에서 얻은 모델 답이 정확한지는 검사하지 않았다.

## 실행하지 않은 것과 실제 원본 명령

원본 HTTP 접속, 브라우저 기동, 모델 호출, 로그인, 폼 시도, CAPTCHA 접근, 내려받기, Docker 조작, DNS 및 WHOIS 조사, 다섯 웹 비교, 비용 실측과 독립 모델 검증은 실행하지 않았다. 보류된 `site_installer.py`도 import하지 않았다.

사용자가 지정한 다음 파일은 읽기를 시도했으나 존재하지 않았다.

```text
.tmp/decoy-generic/installer-targets/wordpress/deployment.json  (저장소 루트 기준)
```

따라서 실제 원본 주소와 포트를 확인하지 못했다. `register_installer_target.py`의 기록 작성 코드에는 `public_origin`이 있으나 지정 파일의 실제 키와 값은 미확인이다. 임의 포트와 다른 경로를 대신 쓰지 않았다. 원본 명령은 해당 파일이 있고 `public_origin`에 유효한 공개 주소가 들어 있다는 조건으로 그 값을 읽는다. 해당 주소가 내부 Docker 망에서만 보이는 경우, 브라우저를 실행하는 환경에서도 그 주소에 닿을 수 있어야 한다. 이번 구현은 Docker 배포나 브라우저 망 연결을 자동으로 바꾸지 않는다.

실제 원본에서 실행할 한 줄은 다음과 같다. 이번 회차에는 실행하지 않았다.

```powershell
python -B -m site_analysis.analyze --origin-url ((Get-Content -Encoding UTF8 -Raw '../../.tmp/decoy-generic/installer-targets/wordpress/deployment.json' | ConvertFrom-Json).public_origin) --out ../../.tmp/site-analysis/wordpress-analysis.json --runs 2 --model gpt-6-sol
```
