# 검증 기록 — 0.13.0 (고위험 격리 도입 시점)

> **이 문서는 0.13.0 당시의 날짜 기록이고, 그 뒤 갱신하지 않았다.** 현재 패키지 버전은
> `pyproject.toml` 기준 **0.14.0** 이다. 아래 수치(pytest 56 · Node 5)는 0.13.0 시점 값이다.
> 그 뒤의 미끼 경로 단일화(`#48`)와 사이트 일반화(`#52`)로 스위트가 커졌고,
> [병합 당시 리팩토링 보고서](https://github.com/WHS4-RUBY/ruby/blob/4b0b82920e218d02c8b292e06619416f2ea2e20a/docs/refactor-summary.md) 9절의 측정 기록은 `#52` 병합
> 시점 기준 **pytest 92건 + lure UI Node 6건**으로 적고 있다. 지금 수치를 직접 확인하려면
> `python -m pytest -q` 와 `node --test tests/test_lure_ui.cjs` 를 돌린다(의존성 설치가 필요하므로
> 측정은 Docker 또는 CI 에서 한다).
>
> 아래 본문은 **고위험 격리 핸들러를 처음 넣었을 때 무엇을 어떻게 확인했는지**의 기록으로 읽는다.
> 원본 호출 0회, 위험 등급 서명 위조 거절, 영속 격리 같은 성질은 이후 버전에서도 테스트로 유지된다.

- Python 자동 테스트 `56 passed`, 화면 스크립트 Node 테스트 `5 passed`.
- 기존 중위험 테스트 48개는 유지되었다. 원본 응답 오버레이, V1 32단계 가짜 로그인, V2 40단계 순환, 서명·nonce 검증과 단일 decoy 라우팅이 계속 통과한다.
- 새 고위험 테스트는 V1/V2 각각 `/`, `/login`, 설정된 로그인 경로, `/admin`, `/.env`, `/api/*`, `/rest/*`, 정적 파일, 임의 원본 경로, `/ftp`, `/ops/*`, 다양한 HTTP 메서드를 요청했다. 구성된 모의 origin의 호출 수는 **0**이었다.
- 고위험 서명 위험 등급의 위조·삭제·추가를 거절한다. 일반 중위험 서명은 기존처럼 원본 응답을 받는다. 고위험으로 확인된 actor는 이후 중위험 서명을 보내거나 프록시가 재시작해도 로컬 격리 응답만 받는다.
- 로컬 실험 게이트웨이의 `risk='high'` 경로 역시 모의 origin 호출 없이 로컬 404를 반환했다.
- V1·V2의 고위험 `/`와 `/ops/service`가 동일한 다섯 카드 대시보드를 반환하고 모든 메뉴가 로컬에서 200으로 열리는지 확인했다. 새 `/ops/service/audit`은 합성 기록만 보여 준다. 중위험 `/ops/service` 화면과 해당 Audit 경로의 기존 404는 유지된다.
- 이번 수정본은 모의 원본을 이용한 자동 테스트로 검증했다. 공식 Juice Shop 컨테이너와 실제 탐지팀을 이용한 종단 간 공격 실험은 이번 검증에 포함되지 않는다.

고위험 요청은 같은 프록시 안의 격리 핸들러를 거치므로 원본 응답을 이용한 화면 복제는 제공하지 않는다. 탐지팀은 고위험 actor를 계속 프록시로 라우팅해야 한다.
