# 경로 별칭 v4 PR 검증과 연구 범위

## 변경 내용

- 별칭 저장소를 PostgreSQL에서 단일 호스트 SQLite WAL 파일로 전환한다.
- audit 모드, 앱·경로별 적용 범위와 readiness 검사를 추가한다.
- 응답 URL 재작성과 쿼리·본문 dispatcher 검사를 보강한다.
- 관리자 API의 끝 슬래시 처리를 수정하고, 원본 API 직접 호출 이후에도 기존 탭 별칭을 유지한다.
- 만료된 자기 별칭의 GET/HEAD를 복구하고, 검증된 앱에서 POST 307 복구를 선택할 수 있게 한다.
- 미확인·전체 클라이언트 수를 제한하고, 상한 검사에서 만료된 pending 및 confirmed 유휴 항목을 회수한다.

## 기존 실험과 주장 범위

`22a5fa71`을 대상으로 보고된 마지막 A/B 한 쌍에서 off는 11요청·127.20초에 관리자 권한 획득이 확인됐고, enforce는 29요청·209.94초 실행 종료까지 성공이 관측되지 않았다. 입력 처리량은 4.01배, 출력 토큰은 1.95배였다. 일반 사용자 핵심 흐름 10/10, 추가 화면 18/18, 관리자 흐름 5/5가 두 조건에서 통과했다. 추가 화면 검사는 모든 기능의 최종 제출 완료를 의미하지 않는다.

이는 HTTP 전용 모델 1종의 단일 실험이며, 이번 상한 회수 수정 후 LLM 공격이나 전체 브라우저 A/B를 새로 실행한 결과는 아니다. 300초 전체 방어, 일반적인 성공률 또는 지속적인 토큰 비용 증가로 해석하지 않는다.

공격자는 자기 세션의 공개 JS·브라우저 네트워크에서 별칭을 재탐색할 수 있다. 미확인 pending 별칭은 기본 300초 동안 쿠키 없이도 사용할 수 있으며, confirmed 이후에는 소유자 쿠키를 요구한다. 별칭은 공격 비용을 높이는 보조 기법으로 평가하고 대상 앱의 인증·인가와 다른 방어를 함께 적용한다. 자동화된 재탐색·적응형 브라우저 공격·반복 A/B는 추가 검증 대상이다.

## 배포 조건

기본 모드는 off이다. SQLite는 단일 호스트 범위이며 다중 호스트 공유와 실서비스 부하·장애 회복은 별도 검증이 필요하다. PostgreSQL 행을 자동 이전하지 않으므로 기존 enforce 사용자의 열린 탭은 전환 시 새로고침이 필요하다. 이전 `PATH_ALIAS_DB_URL` 설정은 제거하고 PostgreSQL 볼륨은 롤백 기간 동안 보존한다. 자세한 절차는 [운영 가이드](path-alias-operations.md#92-기존-postgresql-설치에서-전환)를 따른다.
