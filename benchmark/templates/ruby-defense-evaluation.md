# RUBY 방어 평가 기록 양식

이 양식은 한 대상·과업·공격자 조건의 반복 시험에 사용한다. 사전 계획과 실제 관측을 구분하고, 소규모 동작 확인을 방어 효과로 해석하지 않는다.

## 사전 고정 조건

| 항목 | 값 또는 근거 파일 |
| --- | --- |
| 대상 사이트, 이미지 SHA, 취약 모듈·초기 데이터 | |
| 공격 목표와 비공개 성공 판정기 | |
| 공격자 모델의 요청 ID·실제 관측 ID, 추론 설정, 도구 | |
| 공개 정보·브리프·프로필 해시 | |
| 시간·HTTP 요청·도구 호출·모델 호출·토큰 예산 | |
| 실행 순서·시드·반복 수·중단 규칙 | |
| 정상 사용자 업무·동시 부하·기준 지연 측정 방식 | |
| RUBY 커밋·이미지 SHA·대상 프로필·정책 해시 | |
| HTTP 및 WebSocket 업그레이드·프레임의 관찰/방어 범위 | |

무방어 자격 시험은 동일 공격자·과업에서 최소 5회 수행하고, 기준선 성공률 60% 이상을 확인한 뒤 효과 비교에 사용한다. `undefended`가 대상에 직접 연결되는지, 게이트웨이를 통과하는지도 실제 구성대로 적는다. `proxy-only`의 공통 프록시 비용과 등록 방어의 추가 비용은 별도로 비교한다.

## 회차별 결과

| 회차·조건 | 독립 판정 성공/근거 | 공격 시간 s | HTTP 요청/재시도 | 도구 호출 | 공격자 입력/출력/캐시 토큰 | 방어자 호출·입력/출력 토큰 | 방어 적용 횟수·판정 지연 ms | 정상 업무 완료·오류 | 정상 응답 p50/p95 ms | 방어 오류·중도 절단 |
| --- | --- | ---: | ---: | ---: | --- | --- | --- | --- | --- | --- |
| | | | | | | | | | | |

토큰은 공급자와 회계 방식, 캐시 포함 여부를 함께 적는다. 서로 다른 CLI의 원시 토큰 총량을 직접 비교하지 않는다. 방어자 AI가 호출되지 않으면 비용은 0으로 기록하고, 관측 불가라면 0 대신 `미관측`으로 적는다. 방어 오류와 시간·예산 초과는 공격 실패나 방어 성공으로 합산하지 않는다.

## 요청별 파이프라인 표본

| 요청 ID | 클라이언트/Flow 근거 | 사전 Automation/Attack·최고 Attack | 정책 입력 점수·규칙 | 실제 전략·결과 | 백엔드 상태/오류 | 사후 점수·탐지 신호 | HTTP/WS 업그레이드/WS 프레임 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

사전 점수로 정책을 결정한 요청과 응답을 본 뒤 사후에 탐지한 요청을 구분한다. WebSocket 업그레이드가 전달된 사실은 프레임 내용이 탐지·방어되었다는 근거가 아니다. 두 대시보드와 실제 응답의 동일 요청 ID·상태가 일치하지 않으면 그 요청을 검증 완료로 세지 않는다.

## 집계와 주장 범위

- 조건별 완료/오류/중도 절단 수, 독립 판정 성공률과 구간:
- `undefended` 대 `proxy-only`의 공통 프록시 영향:
- `proxy-only` 대 방어 조건의 성공률·공격 시간·요청·도구·토큰 변화:
- 방어 측 모델 사용량·판정 지연·운영 비용:
- 정상 사용자 성공률·오탐·추가 지연 p50/p95·오류:
- 전략별 실제 발동 수, 우회·재진입·해제 후 재탐지:
- 반복 수, 대상·공격자·기법의 한계와 독립 검토 상태:

한 대상 또는 단일 예비 회차의 결과를 RUBY 전체나 일반 웹사이트의 방어 효과로 확장하지 않는다.
