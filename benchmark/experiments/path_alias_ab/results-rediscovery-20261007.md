# 경로 별칭 재발견 A/B 실험 (2026-10-07)

## 방법

- 로컬 Docker의 동일한 Juice Shop/방어 프록시 이미지를 사용했다. A는 `PATH_ALIAS_MODE=off`, B는 `enforce`이다.
- `A→B`, `B→A`, `A→B` 순서로 각각 15분씩, 총 90분 실행했다. 각 구간은 새 컨테이너와 새 SQLite 상태로 시작했다.
- 두 조건 모두 Chromium 캐시와 서비스 워커를 껐다. 세 개의 독립 브라우저 세션이 45초마다 정상 사용자 흐름을 반복했다.
- 한 세션은 매 회차 직접 경로와 이전 별칭을 확인했다. B에서는 그 요청에 따른 별칭 교체 뒤 공개 화면과 JS를 다시 읽고 검색 경로를 재발견했다. A에서도 동일한 화면 재탐색을 수행했다.
- 재탐색 시간은 화면 재탐색 시작부터 새 경로의 유효성 확인 및 CDP 수신 완료 대기 100ms까지다. 브라우저 요청 수와 전송량은 CDP의 `Network.responseReceived` 및 `Network.loadingFinished.encodedDataLength`로 측정했다. 별도 API 유효성 검사 요청 1건은 브라우저 요청 수에 포함하지 않았다.

## 결과

여섯 구간 모두 900초 이상 완료됐다. 구간마다 정상 흐름 60/60회, 재탐색 20/20회, 프로토콜 검사 160/160회가 통과했다. 브라우저 HTTP 304 응답은 각 구간 0건이었다. B의 직접 경로 60건과 이전 별칭 60건은 예상대로 404였고, 다른 세션의 유효 경로는 유지됐다.

| 지표 | A (60회) | B (60회) |
| --- | ---: | ---: |
| 재탐색 시간 중앙값 | 512ms | 590ms |
| 재탐색 시간 p95 | 654ms | 631ms |
| 재탐색당 브라우저 요청 중앙값 | 31건 | 31건 |
| 재탐색당 `main.js` 요청 | 1건 | 1건 |
| 재탐색당 전송량 중앙값 | 2,348,025바이트 | 2,348,417바이트 |
| 재탐색당 JS 전송량 중앙값 | 1,782,154바이트 | 1,782,849바이트 |

B는 이전 주소를 차단하지만 이 고정된 공개 화면 재탐색 절차에서 새 별칭은 60/60회 발견됐다. 따라서 별칭 교체가 지속적인 경로 접근을 막는다는 주장은 이 실험으로 뒷받침되지 않는다. 이번 실험은 적응형 LLM 공격을 실행하지 않았다. 한 호스트의 세 A/B 쌍과 SQLite 저장소를 사용했으므로 성능 차이는 기술적 관찰값이다. 15분 창은 30분 epoch 만료 효과를 측정하지 않는다.

재실행: `run_rediscovery_ab.py --duration 900 --output <새 출력 디렉터리>`. 완료 후 `analyze_rediscovery_ab.py <출력 디렉터리>`로 여섯 구간의 유효성과 집계를 확인한다. 원시 Docker 로그와 JSONL 기록은 `artifacts/rediscovery-ab/formal-20261007-01/`에 보관되며 Git에서는 제외된다.
