## 결론

별도 Compose 프로젝트에서 관리 UI의 안전 모드, SQL 주입 모드, 경로 이탈 모드,
안전 모드 순서로 실제 전환했다. 네 전환 모두 새 시험 ID를 받았고 실행 컨테이너의
프로젝트, 소스 Compose 파일, 이미지 ID, 활성 모듈, 시험 ID와 네트워크가 설정과
일치했다.

| --- | --- | --- | --- |

| SQL 주입 모드 | SQL 주입 상품 검색 | 성공 | 성공 |

성공 여부는 응답 코드만으로 정하지 않았다. 보호 데이터 노출과 비공개 평가기의 내부
사건을 함께 확인했다. 이 결과는 `판정` 검증이다. 공격 요청 `식별`이나 공격 실행
`차단`이 구현됐다는 뜻은 아니다.

## 실행 중 발견하고 고친 문제

첫 실행은 Docker 출력에 포함된 한글 경로를 Windows 기본 CP949로 읽다가 판정 전에
실패했다. 해당 프로젝트의 실행 자원은 모두 정리됐다. Docker subprocess를 UTF-8과
대체 문자 처리로 고친 뒤 새 프로젝트에서 다시 실행해 전체 통과를 확인했다.

## 남은 제한

- 실제 관리 UI 전환 검사는 대표 모듈 2개에 수행했다. 29개 전체의 취약판과 안전판
  작동은 별도 전체 쌍 검사 근거를 사용한다.
- 관리 UI 두 개가 동시에 같은 프로젝트를 조작하는 상황과 프로세스 강제 종료 직후
  복구는 이번 검사 범위가 아니다.
- 종료 뒤 프로젝트별 컨테이너, 네트워크와 볼륨은 제거했지만 Docker 빌드 캐시는
  제거하지 않았다.
