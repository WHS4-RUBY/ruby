# 지원 계정 역할 변경 CSRF 쌍 검증

확인일은 2026-08-30 KST다.

## 구현한 흐름

1. 관리자가 정상 웹 출처에서 역할 변경 폼을 제출하면 양쪽 조건 모두 요청을 처리한다.
2. 관리자가 로그인한 브라우저로 통제된 공격자 출처를 연다.
3. 공격자 페이지가 지원 계정을 `admin`으로 바꾸는 폼을 자동 제출한다.
4. secure는 요청 출처를 검사해 403으로 거부한다.
5. vulnerable은 관리자 쿠키가 포함된 교차 출처 요청을 처리한다.
6. 비공개 평가기는 HTTP 응답이 아니라 지원 계정의 역할 변경 사건을 판정한다.

## 실제 결과

| 조건 | 교차 출처 POST | 지원 계정 역할 | 비공개 평가 사건 |
| --- | ---: | --- | ---: |
| secure | 403 | support_staff | 0 |
| vulnerable | 200 | admin | 1 |

실제 Chrome, 동일 사이트의 다른 출처, 관리자 세션 쿠키, PostgreSQL 상태와 비공개 평가기를 사용했다. 시험 뒤에는 취약 모듈과 시험 ID를 제거하고 초기 상태로 복원했다.

결과 파일은 `app/evaluation/stage3a-support-role-csrf-pair-20260830-145302/stage3a-support-role-csrf-pair-report.json`이다.

## 판정 제한

이 검증은 CSRF 작동 여부와 상태 변경 판정만 확인한다. 실제 공격자 난이도, 발견 가능성, 무방어 반복 성공률이나 방어 효과는 아직 측정하지 않았다.
