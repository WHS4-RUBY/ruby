# 브랜치 변경 이력 해설

문서 분류: `회고 해설`

## 작성 이유

공통 기준 커밋 `c79de21` 이후 `a3b7d67`까지 벤치마크 브랜치 커밋은 18개다. 커밋 제목은 남아 있지만 18개 모두 본문이 비어 있다. 특히 최초 커밋 `bf7789a`는 저장소 전체에서 323개 파일을 바꾸고 57,001줄을 추가했으므로 제목만으로는 검토 범위를 파악하기 어렵다.

이미 원격 저장소에 존재하는 커밋을 force push로 다시 쓰지 않는다. 이 문서는 당시 diff, 현재 코드, 테스트, 설정과 증거 파일을 확인해 기존 커밋을 회고해서 설명한다. 원래 작성자가 기록하지 않은 의도까지 사실로 확정하지 않는다.

## 비교 기준

- 기준 커밋: `c79de2189cdcab9180247b17690317667f70b36f`
- 해설 대상 마지막 커밋: `a3b7d67d1a7b28d200eb9f0e23710933a847e934`
- 대상 경로: `benchmark/benchmarks/web-defense-benchmark/`
- 확인 방법: 각 커밋의 파일 상태, diff 통계, 구현 진입점과 함께 추가된 테스트 및 증거 확인

아래 검증 수치는 이 문서를 작성하면서 다시 실행한 결과가 아니다. 각 커밋에 저장된 문서와 evidence가 기록한 당시 결과를 옮겼다. 현재 환경에서도 같은 결과가 나온다는 뜻으로 사용하지 않는다.

- React와 FastAPI로 구성한 쇼핑몰 업무 흐름

이 커밋만으로는 각 파일이 만들어진 순서, 대안과 선택 이유를 복원할 수 없다. [코드 구성과 책임 안내](codebase-guide.md)는 현재 남은 코드의 책임을 보완해서 설명한다.

## 해설로 복원할 수 없는 내용

다음 항목은 당시 커밋 본문이 없으므로 현재 diff만으로 확정할 수 없다.

- 최초 323개 파일을 한 커밋으로 묶은 판단 과정
- 최초 구현 전에 검토한 대안과 폐기 이유
- 각 과거 도구 버전을 계속 유지하기로 한 당시 결정
- 로컬에서 실행했지만 저장하지 않은 명령과 실패 결과

해당 내용을 아는 참여자가 확인하면 이 문서에 근거와 함께 보충한다. 기억에만 의존한 설명은 `회고`라고 표시한다.

## 이후 커밋 본문 형식

앞으로 벤치마크 커밋은 제목 아래에 최소한 다음 내용을 기록한다.

```text
<type>(benchmark): <한 가지 변경 목적>

Why:
- 이 변경이 필요한 확인된 문제

What:
- 바꾼 실행 경로, 계약 또는 구성요소
- 의도적으로 바꾸지 않은 범위

Validation:
- 실제 실행한 명령과 결과
- 실행하지 못한 검사와 이유

Security/compatibility:
- 공격자 격리, 평가기, 방어 인터페이스 또는 다른 컴포넌트 영향
```

증거만 추가한 커밋도 실행 조건, 표본 수, 성공 및 실패 수, 결과가 적용되는 표적과 남은 검토를 본문에 적는다. 제목만으로 결과의 의미를 대신하지 않는다.
