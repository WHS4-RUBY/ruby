# 시나리오 작동 검증

확인일: 2026-09-11 KST

## 결론

자체 시나리오는 현재 소스로 이미지를 다시 만든 뒤 준비된 공격 절차를 실행했다. 원본 CVE는 제품 버전 쌍에 같은 참조 공격을 실행했다. 자체 시나리오 29개와 원본 CVE 5개 모두 취약판에서 목표가 발생했고 안전판 또는 수정판에서는 같은 목표가 발생하지 않았다. Langflow는 2026-09-12에 설정된 image digest와 실행 컨테이너의 image ID까지 일치하는지 다시 확인했다.

이 결과는 취약점과 성공 판정기가 작동한다는 뜻이다. AI가 공격을 스스로 찾는다는 뜻도, RUBY 식별기와 차단기가 공격을 막는다는 뜻도 아니다.

## 공통 검증 방법

1. 자체 시나리오는 현재 소스로 Docker 이미지를 빌드했고, 원본 CVE는 설정된 제품 이미지와 실행 이미지가 일치하는지 확인했다.
2. 시나리오 하나만 켠 취약판에 준비된 공격을 실행했다.
3. HTTP 코드만 보지 않고 내부 사건, 상태 변경, 파일 또는 브라우저 실행을 확인했다.
4. 같은 공격을 안전판 또는 수정판에 실행해 목표가 생기지 않는지 확인했다.

전체 실행 결과는 [all-pair-checks.json](../../evidence/20260911/pair-checks-complete-evidence/all-pair-checks.json)에 있다. 검사기 18개와 시나리오 34개가 모두 통과했다.

## 세 기능의 용어

- `판정`: 공격 성공 여부를 내부 상태, 파일이나 브라우저 실행으로 확인한다.
- `식별`: 관측한 요청이 공격 요청인지 분류한다.
- `차단`: 공격이 실행되지 않도록 요청을 막거나 바꾼다.

`공격 재현 통과`는 판정 결과다. 식별이나 차단 결과가 아니다.
