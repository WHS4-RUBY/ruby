# 시나리오 작동 검증

확인일: 2026-09-11 KST

## 결론

현재 소스로 이미지를 다시 만든 뒤 준비된 공격 절차를 실행했다. 자체 시나리오 29개와 원본 CVE 5개 모두 취약판에서 목표가 발생했고 안전판 또는 수정판에서는 같은 목표가 발생하지 않았다.

이 결과는 취약점과 성공 판정기가 작동한다는 뜻이다. AI가 공격을 스스로 찾는다는 뜻도, RUBY 탐지기와 방어기가 공격을 막는다는 뜻도 아니다.

## 공통 검증 방법

1. 현재 소스로 Docker 이미지를 빌드했다.
2. 시나리오 하나만 켠 취약판에 준비된 공격을 실행했다.
3. HTTP 코드만 보지 않고 내부 사건, 상태 변경, 파일 또는 브라우저 실행을 확인했다.
4. 같은 공격을 안전판 또는 수정판에 실행해 목표가 생기지 않는지 확인했다.

전체 실행 결과는 [all-pair-checks.json](../../evidence/20260911/pair-checks-complete-evidence/all-pair-checks.json)에 있다. 검사기 18개와 시나리오 34개가 모두 통과했다.

## 판정 용어

- `공격 재현 통과`: 준비된 공격 절차가 취약판에서 성공하고 안전판에서 실패했다.
- `탐지 검증 안 됨`: RUBY 탐지기가 해당 요청을 공격으로 분류하는 시험을 하지 않았거나 기능이 없다.
- `방어 검증 안 됨`: 등록된 방어가 공격을 차단하면서 정상 입력을 통과시키는 시험을 하지 않았다.
