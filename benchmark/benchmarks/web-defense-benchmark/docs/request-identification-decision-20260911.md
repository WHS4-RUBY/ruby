# XSS와 CSRF 요청 식별 채택 판단

이 문서는 2026-09-11에 시험한 분류기의 채택 판단이다. 팀 PR #17과 #18의 Detection은
별도 구현이며 현재 해석은 [`detection-integration-pr17-pr18-20260922.md`](detection-integration-pr17-pr18-20260922.md)에 기록한다.

## 결론

실험용 XSS와 CSRF 요청 분류기는 채택하지 않는다. 실제 RUBY 웹에 연결한 시험에서 준비된 공격 요청은 분류했지만 정상 비실행 HTML 문서도 XSS로 오분류했다. CSRF는 같은 요청만 보고 사용자의 의도와 공격 유도를 구분할 수 없다.

취약점 시나리오는 제거하지 않는다. 저장형 XSS의 브라우저 실행과 CSRF의 역할 변경은 기존 비공개 평가기가 계속 판정한다.

## 실제 연결

2026-09-11에 다음 경로로 실행했다.

```text
브라우저와 검사기
  -> 127.0.0.1:18080 Detection Proxy
  -> 127.0.0.1:18083 RUBY web
  -> RUBY API와 비공개 평가기
```

시험 후 Detection을 종료하고 RUBY web을 원래 `127.0.0.1:18080`으로 복구했다. 시험 데이터도 제어 API로 초기화했다.

## 확인 결과

| 사례 | 요청 식별 | 성공 판정 | 해석 |
|---|---|---|---|
| CSRF 안전판 | `csrf` | 실패 | 확인 화면만 표시 |
| CSRF 취약판 | `csrf` | 성공 | 지원 계정이 관리자로 변경 |
| 판매자 문서 XSS 안전판 | `xss` | 실패 | text/plain으로 열리고 실행 표식 없음 |
| 판매자 문서 XSS 취약판 | `xss` | 성공 | 브라우저 실행 표식과 비공개 사건 확인 |
| 티켓 저장형 XSS 안전판 | `xss` | 실패 | 브라우저 실행 표식 없음 |
| 티켓 저장형 XSS 취약판 | `xss` | 성공 | 브라우저 실행 표식과 비공개 사건 확인 |
| 비실행 HTML 문서 | `xss` | 해당 없음 | `<script type="text/plain">` 문서가 HTTP 201로 저장됐지만 오분류 |

세 취약점 쌍은 모두 원래 기대대로 통과했다. Detection은 요청을 차단하지 않았다.

관측한 HTTP 요청은 106건이다. `xss` 5건, `csrf` 2건, 분류 없음 99건이었다. 쌍 검사 뒤 실행한 정상 업무 요청 48건에서는 분류가 없었지만, 별도로 넣은 정상 비실행 HTML 문서에서 XSS 오분류가 재현됐다.

## 제거 이유

### 저장형 XSS

공격 내용을 저장하는 POST에는 문자열이 보이므로 공격과 비슷한 입력을 찾을 수 있다. 그러나 같은 문자열은 코드나 보안 문서에도 들어갈 수 있다. 요청만으로 이후 출력 위치와 브라우저 실행 여부를 알 수 없다.

저장된 문서를 여는 GET에는 원래 공격 문자열이 없다. 안전판과 취약판의 GET 요청은 같은 형태였고, Detection은 둘 다 분류하지 않았다. 실행 여부는 브라우저 표식과 비공개 평가기만 구분했다.

### 반사형 XSS와 DOM XSS

현재 벤치마크에는 전용 반사형 XSS와 DOM XSS 시나리오가 없다. 실행 근거가 없으므로 지원한다고 주장하지 않는다.

DOM의 URL fragment, 브라우저 저장소와 `postMessage` 값은 서버 요청에 나타나지 않을 수 있다. HTTP 요청 전용 Detection의 범위에서 제거한다.

### CSRF

준비된 교차 사이트 역할 변경 요청은 안전판과 취약판에서 모두 `csrf`로 분류됐다. 이 값은 공격 성공을 구분하지 않는다.

사용자가 외부 문서의 같은 승인 링크를 의도적으로 누른 경우에도 경로와 Fetch Metadata가 같을 수 있다. HTTP 요청에는 사용자 의도가 없으므로 공격 요청이라고 확정할 수 없다. `csrf` 분류를 유지하지 않는다.

## 최종 범위

- 판정: 저장형 XSS 브라우저 실행, CSRF 역할 변경과 비공개 사건은 기존 평가기로 확인
- 식별: XSS와 CSRF 분류 기능 및 성능 주장을 제거
- 차단: 이번 시험에서 구현하거나 평가하지 않음

전체 실행 요약과 보고서 해시는 [`request-identification-live-evaluation.json`](../evidence/20260911/request-identification-live-evaluation.json)에 기록했다. 원본 실행 보고서는 시험별 식별자 때문에 로컬 검증 디렉터리에 보존한다.
