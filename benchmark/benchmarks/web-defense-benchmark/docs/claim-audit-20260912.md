# 주장과 증거 교차 검토

이 문서는 2026-09-12 당시 저장소 주장에 대한 검사다. 팀 PR #17과 #18 이후의 현재
Detection 구조는 [`detection-integration-pr17-pr18-20260922.md`](detection-integration-pr17-pr18-20260922.md)를 따른다.

확인일: 2026-09-12 KST

## 결론

독립 검토에서 문서의 강한 주장 8개와 증거 연결이 부족한 표현 2개를 찾았다. 현재 코드와 저장된 증거에 맞게 모두 수정했다. 기능 범위 34개는 줄이지 않았다.

XSS와 CSRF에 대한 현재 결론은 다음과 같다.

- `판정`: 준비된 저장형 XSS와 CSRF 시나리오에서 공격 성공 여부를 확인했다.
- `식별`: XSS와 CSRF 공격 요청을 안정적으로 분류하는 기능은 채택하지 않았다.
- `차단`: XSS와 CSRF 실행 차단을 구현하거나 검증했다고 주장하지 않는다.
- DOM 기반 XSS와 반사형 XSS는 현재 전용 시나리오가 없다.

## 유지한 결과

- 2026-09-11 준비된 pair 실행에서 자체 시나리오 29개와 원본 CVE 5개가 기대한 안전판 및 취약판 차이를 보였다.
- 원본 CVE 5개는 준비된 공격 절차에서 취약판 성공과 수정판 실패가 기록됐다.
- Langflow는 2026-09-12 고정 digest, 로컬 image ID와 실행 컨테이너 image ID를 확인한 재실행에서도 기대한 차이를 보였다.
- 원본 CVE 컨테이너 10개의 순차 네트워크 검사는 통과했다.
- 과업 지정 SQL 상품 검색과 `static-guard` v3의 저장된 수치는 유지한다. 실제 모델 ID 미관측, 같은 표적에서 조정한 기준 fixture와 독립 검토 대기 때문에 방어 효과 근거로 사용하지 않는다.

## 남은 제한

- 여러 worktree의 동시 캠페인과 강제 종료 직후 정리는 검증되지 않았다.
- 호스트에서 실행되는 AI CLI 자체는 독립 VM 안에서 검증하지 않았다.
- 실제 방어 제품, 다른 공격자와 전체 34개에 대한 방어 효과는 측정하지 않았다.
- 준비된 공격 절차의 성공은 AI가 공격을 스스로 찾아낸 결과가 아니다.
