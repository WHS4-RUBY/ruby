# 2026-09-17 본 실험 대상 결정

## 결론

취약점 구현과 재현 자료 34개는 삭제하지 않는다. 본 실험에서는 29개만 사용한다. XSS 및
CSRF 관련 대상 5개는 공격자 실행, 요청 식별과 방어 효과 비교에서 제외한다. 해당 5개의
취약점 재현과 공격 성공 판정 근거는 보존한다.

안전판과 원본 제품 수정판은 취약판의 동작 차이를 확인하는 재현 대조군이다. 본 실험 조건에는
취약판만 사용한다.

## 본 실험 대상

본 실험 대상은 29개다. RUBY 웹 대상은 제외 대상 3개를 뺀 26개다. 원본 CVE는 다음 3개다.

- `cve-original:CVE-2024-23897`
- `cve-original:CVE-2024-36401`
- `cve-original:CVE-2025-3248`

전체 목록의 기계 판독 원본은
[`../app/configs/main-experiment-target-policy-v1.json`](../app/configs/main-experiment-target-policy-v1.json)이다.

## 코드 적용 위치

- 캠페인 실행기는 대상을 생략하면 정책에 적힌 29개를 사용한다.
- 제외 대상 5개를 명시하면 Docker 정리나 표적 준비 전에 실행을 거부한다.
- 관리 UI는 구현 34개를 목록과 재현용 모듈 전환 화면에 유지한다. 실험 실행 선택에는 29개만 표시한다.
- 확증 분석기는 같은 정책을 읽고 제외 대상이 섞인 방어 효과 집계를 거부한다.
- 실행 봉인에는 정책, 스키마, 호환용 제외 목록과 각 파일의 SHA-256을 함께 기록한다. 해시는 원본 설정을 대신하지 않는다.

2026-09-17 이전의 34개 전체 캠페인 설정과 v10, v11 실행 기록은 당시 기록으로 보존한다.
현재 본 실험 범위를 정하는 근거로 사용하지 않는다.

## 범위 밖 작업

요청 식별 로직의 리팩터링은 식별 컴포넌트 담당 범위다. 외부 방어 모듈 구현은 방어 컴포넌트
담당 범위다. 이 결정은 두 컴포넌트의 구현을 취약점 웹에 복사하지 않는다. 이후 연결되는 방어
모듈은 본 실험 대상 29개에서 무방어 조건과 같은 공격자, 시간과 예산으로 비교한다.

## PR #17과 #18 반영

2026-09-22에 팀 `main`의 PR #17과 #18을 반영했다. Detection에는 Fingerprint 기반
Client Flow 집계, XSS 페이로드 및 CRS 신호, CSRF Origin 및 Referer 신호가 있다. 이
신호는 요청 분류의 입력이며 취약점 웹의 비공개 성공 판정을 대신하지 않는다. 현재 정책은
점수 구간에 따라 지연 계획을 만들며, XSS 또는 CSRF 실행 차단과 방어 효과를 새로 검증한
결과가 아니다.

따라서 본 실험 29개와 제외 대상 5개는 그대로 유지한다. 제외 대상을 다시 본 실험에 넣는
경우에는 별도 범위 결정, 정상 입력 오탐 시험, 방어 조건 반복 비교와 독립 검토가 필요하다.
