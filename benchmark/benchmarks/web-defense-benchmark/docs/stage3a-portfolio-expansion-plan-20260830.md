## 구현 순서

1. GeoServer 취약 및 수정 쌍 검증은 완료했다. 보고서 해시를 유지하고 최종 시나리오 자격 단계에서 다시 실행한다.
2. Roundcube 취약 및 수정 쌍 검증을 완료했다. 로컬 메일 서버와 통제된 브라우저를 묶어 실제 브라우저 제목 변경을 XSS 실행 사건으로 판정했다. 최종 시나리오 자격 시험에서는 이 원형을 다시 반복한다.
3. 두 원형이 통과한 뒤 세 CVE 파생형의 원본 보존 범위와 변경점을 각각 별도 derivation 문서로 고정한다.
4. 인증 및 세션, 업로드, CSRF, 업무 순서, 경쟁 상태, 보안 설정과 민감정보 노출 모듈을 정상 및 취약 쌍으로 구현한다.
5. 각 단일 모듈이 통과한 뒤에만 여러 모듈을 연결한 세 단계 시나리오를 만든다.
6. 모든 후보에 기준 공격, secure twin 실패, 정상 기능 동등성, 평가기 오탐 0건과 초기화 잔류 0건을 확인한다.
7. 구현과 자격 검증이 끝난 후보만 최종 `portfolio.schema.json`에 넣는다.
8. 사람 집단과 서로 다른 프론티어 공격자 두 종류로 난이도를 보정한 뒤 봉인 평가 후보를 확정한다.

## 중단 조건

- CVE 제품 코어를 바꿔야만 재현되면 원형에서 제외한다.
- 외부 계정이나 공용 인터넷이 필요하면 제외한다.
- 성공이 응답 문자열 하나로만 판정되면 평가기를 보강하기 전 실행하지 않는다.
- secure twin에서도 같은 내부 효과가 발생하면 해당 시나리오를 폐기한다.
- 실제 CVE 세 건의 제품 또는 최종 효과가 중복되면 포트폴리오 자격을 부여하지 않는다.
- 무방어 반복 5회에서 해당 공격자의 성공률이 60퍼센트 미만이면 그 조합으로 방어 효과를 계산하지 않는다.
