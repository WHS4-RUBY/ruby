# 개발 계획과 완료 조건

## 0단계, 계약 고정

작업:

- 웹사이트 업무 범위와 사용자 역할 확정
- 시나리오, 공개 브리프, 배포, 평가기와 미끼 등록 계약 검증
- 실행 전 승인, 시험 결과, 자격 보고서와 비교 묶음 계약 검증
- 개발, 조정과 봉인 평가 데이터의 분리 규칙 확정
- 대상 이미지, 시나리오와 결과 산출물의 해시 규칙 확정
- 취약점 포트폴리오, 난이도 보정과 시나리오 자격 기준 확정
- 방어 연결 유형, 구현 충실도와 누락 구성요소 기록 형식 확정
- 공격자 자율성, 정상 트래픽과 미끼 격리 규칙 확정

완료 조건:

- 정상 및 거부 fixture로 자동 검증되는 계약
- 특정 방어 제품명이 계약 필수 필드에 없음
- 공격자가 평가기 네트워크와 결과를 볼 수 없음
- 시나리오, 방어 기능과 실험 매니페스트의 정상 및 거부 검사가 통과
- `docs/evaluation-contract.md`의 재발 방지 게이트가 계약에 연결됨
- 무방어와 방어 조건의 공통 필드 및 실제 파일 SHA256이 묶음 단위로 일치
- 요청 필드 누락, 비웹 URL, 연결과 기능 모순 및 구형 제로데이 명칭 반례가 거부됨

## 1단계, 정상 웹사이트

작업:

- 인증, 상품, 주문, 고객지원, 판매자와 관리자 기능 구현
- PostgreSQL, 객체 저장소와 worker 연결
- 정상 사용자 시나리오와 결정적 초기 데이터 작성

완료 조건:

- 비회원, 고객, 판매자 직원, 고객지원 직원과 관리자 흐름 통과
- 역할별 접근 제어 검사 통과
- 같은 초기화 시드에서 동일한 상태 생성
- 의도한 취약점이 없는 기준 이미지 생성

## 2단계, 비공개 평가기와 초기화

작업:

- 내부 사건 수집과 성공 판정 구현
- 시험별 데이터, 볼륨과 네트워크 초기화
- 실행 ID, 중단 상태와 산출물 원장 구현

완료 조건:

- 가짜 HTTP 성공 응답만으로 성공 판정 불가
- 공격자 네트워크에서 평가기 접근 불가
- 동일 시험을 초기화한 뒤 상태 잔류 0건

## 3단계, 취약점 모듈

작업:

- 초기 여섯 취약점 범주의 정상 및 취약 구현
- 선행 조건, 공격 결과, CWE와 ASVS 위반 항목 기록
- CVE 원형 한 건을 별도 컨테이너로 연결
- 취약 기준선과 정상 쌍을 동일 업무 상태로 제작

완료 조건:

- 각 취약점의 기준 공격이 실제 내부 효과를 발생시킴
- 비활성 상태에서는 같은 기준 공격이 실패함
- 취약점 이외의 정상 기능 결과가 두 조건에서 동일함
- CVE 원형과 파생형 표시가 혼동되지 않음

## 3A단계, 포트폴리오 확대와 난이도 보정

작업:

- 12개 이상 취약점 계열과 24개 이상 시나리오 구성
- 실제 CVE 원형 3개와 CVE 파생형 3개 이상 포함
- 단일, 두 단계와 세 단계 이상 시나리오 분포 충족
- 사람과 서로 다른 프론티어 공격자 두 종류 이상으로 무방어 보정

완료 조건:

- 모든 봉인 시나리오가 `qualified`와 `calibrated` 상태
- 같은 결함의 경로명만 바꾼 중복 시나리오 0건
- 쉬움, 보통과 어려움이 실제 성공률과 비용 분포로 구분됨
- 취약점 계열, 공격 결과와 난이도 어느 한 축에도 전체의 절반 이상 편중되지 않음

## 4단계, 방어 장치 연결

작업:

- 무방어 어댑터와 방어 HTTP 계약 연결
- 인라인, 수동 미러, 네트워크 센서, 애플리케이션 계측, 외부 미끼와 비동기 상태형 연결 지원
- 요청 및 응답 본문 크기 제한, 시간 초과와 실패 정책 구현
- 미끼 대상은 시나리오 등록 ID로만 선택하도록 제한

완료 조건:

- 차단, 지연, 변환, 응답 교체와 미끼 전달을 각각 검증
- 방어 장치 오류를 무방어 성공으로 숨기지 않고 별도 상태로 기록
- 무방어와 방어 조건의 대상 초기 상태 해시 일치
- 방어 구현 충실도, 모델, 상태 범위와 누락 구성요소가 실행 전에 봉인
- 미끼 조건은 세션 전환과 실제 대상 재진입 정책 검사를 통과

## 5단계, 벤치마크 검증

작업:

- 정상 사용자 오탐 시험
- 비공개 공격 시나리오와 다단계 공격 시험
- 고정 예산, 반복, 무작위 실행 순서와 결과 집계

완료 조건:

- 공격자에게 점수판과 평가기 단서 노출 0건
- 정상 사용자와 공격자 실험을 같은 계측 경로에서 수행
- 공격 단계, 계정 수와 세션 전환을 강제하지 않는 자율 공격 확인
- 성공률 외 시간, 요청 수, 방어 지연, 오류와 미끼 체류 집계
- 한 개 웹사이트와 한 개 취약점 결과를 전체 성능으로 일반화하지 않음
- 예산 소진, 방어 오류와 공격 실패가 서로 다른 결과 상태로 집계됨

## 구현 시작 전 남은 결정

1. 팀 서버에서 사용할 CPU, 메모리, 저장 공간과 Docker 가능 여부 확인
2. 프론트엔드와 API의 이미지 버전 고정
3. 최초 CVE 원형의 제품, 버전, 라이선스와 amd64 지원 확인
4. 개발용 도메인과 포트 배정
5. 저장소 이관 담당자와 PR 단위 확정
6. 난이도 보정에 사용할 사람 집단과 두 프론티어 공격자 확정
7. 첫 방어 장치의 연결 유형과 구현 충실도 확정

서버 자원, 첫 CVE, 보정 공격자와 첫 방어 연결 유형은 실제 구현과 배포 범위를 바꾸므로 확인 후 진행한다.
