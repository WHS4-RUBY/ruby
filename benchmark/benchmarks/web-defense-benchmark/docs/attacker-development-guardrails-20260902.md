# 범용 공격자 개발 반복 방지 규칙

확정일: 2026-09-02 KST

이 문서는 RUBY 웹 방어 벤치마크의 범용 공격자를 개발할 때 지켜야 할 권위 규칙이다. 이후 공격자 전략 변경, 실제 모델 시험과 확대 평가는 이 문서를 먼저 확인하고 진행한다. 기존 실험 기록이나 구현 편의를 이유로 이 규칙을 우회하지 않는다.

## 1. 현재 판정

- v11은 범용 공격자로 검증되지 않았다.
- v11의 문제는 프롬프트만이 아니라 전략 코드에도 있다.
- v11은 경로명을 계열로 분류하고 계열별 점수와 우선순위를 모델에 제공한다.
- 정상적인 객체 ID와 상태 변경도 공격 증거로 과대평가한다.
- 이 구조는 비밀번호 재설정 대상에서 주문 계열을 계속 탐색하고, SQL 주입 대상에서 검색 입력을 거의 시험하지 않는 편향을 만들었다.
- v11은 향후 성능 비교 기준으로만 보존한다. v11 전략 코드에 예외 규칙을 추가해 계속 확장하지 않는다.
- 2026-09-02 작성 중이던 의미 기반 입력 분류 수정은 미완료이며 실제 공격 시험을 실행하지 않았다. 해당 변경은 채택된 설계가 아니다.

## 2. 확인된 절차 실패

1. 코드 구조 검사와 과거 기록 재생을 실제 공격 성능 검증처럼 취급했다.
2. v11 성능을 소규모로 비교하기 전에 전체 24개 시험으로 확대했다.
3. 첫 24개 실행에서 v11이 아닌 v10 프로필이 사용된 사실을 실행 전에 차단하지 못했다.
4. 다음 24개 실제 v11 실행에서도 작은 비교 게이트 없이 진행했다.
5. 실패 원인을 구조적으로 검토하기 전에 의미 분류와 우선순위 규칙을 추가하려 했다.

확인된 결과는 다음과 같다.

| 비교 | 성공 | 성공률 | 요청 수 | 모델 호출 수 |
|---|---:|---:|---:|---:|
| v10 합성 기준 | 12/24 | 50.00% | 1,633 | 506 |
| 실제 v11 | 7/24 | 29.17% | 1,779 | 648 |

이 수치는 같은 시드로 수행한 엄격한 일대일 비교가 아니다. 그러나 v11을 개선 버전으로 채택할 근거가 없고 회귀 가능성이 크다는 판정에는 충분하다.

## 3. 코드와 모델의 역할 경계

### 코드가 담당하는 기능

- 허용된 대상과 격리 환경 확인
- 요청 실행과 세션 분리
- 공개 스키마와 실제 응답 원문 보존
- 요청, 모델 호출, 시간 예산 계산
- 중복 요청과 반복 실패 기록
- 실행한 요청과 실행하지 않은 공개 요청 구조의 집합 관리
- 응답에서 관찰된 값과 이후 요청에서 사용한 값의 집합 관리
- 발생한 상태 변화와 이후 확인된 상태 변화의 집합 관리
- 세션별 상태 코드, 응답 구조와 공개 상태 차이 기록
- 실행 결과, 모델 ID, 설정 해시와 산출물 저장

### 모델이 담당하는 기능

- 공개 스키마와 응답의 의미 해석
- 공격 가설 생성과 우선순위 결정
- 계정, 세션과 객체 관계 추론
- 입력값과 페이로드 작성
- 관찰된 값을 다음 요청에 연결
- 가설의 검증, 반증과 중단 판단

### 코드가 담당하면 안 되는 기능

- 경로명으로 `orders`, `auth`, `products` 같은 공격 계열 결정
- 필드명의 `password`, `token`, `URL`, `file` 같은 단어로 공격 방향 결정
- 취약점 이름, 대상 ID 또는 정답 경로에 따른 분기
- 특정 페이로드나 공격 순서 강제
- 계열별 고정 공격 점수와 고정 우선순위 제공
- 정상적인 상태 변경을 공격 성공 가능성으로 자동 승격

## 4. 전략 상태의 허용 형식

전략 상태는 공격 정답을 제시하지 않고 관찰 가능한 집합 차이만 제공한다.

```text
공개 요청 구조 집합 S
실행한 요청 구조 집합 T
미실행 요청 구조 S - T

응답에서 관찰된 값 집합 V
이후 요청에 사용한 값 집합 C
미사용 관찰값 V - C

관찰된 상태 변화 집합 D
독립 조회로 확인한 상태 변화 집합 Q
미검증 상태 변화 D - Q
```

구조 정규화에는 HTTP 메서드, 공개 경로 템플릿, 입력 위치, 자료형, 본문 형식, 세션과 실제 응답 구조만 사용한다. 경로명과 필드명의 업무 의미를 코드가 해석하지 않는다.

## 5. 넓은 탐색과 깊은 검증의 전환

모델은 최대 세 개의 독립 가설을 유지한다. 각 가설에는 다음 항목이 필요하다.

- 근거가 된 실제 공개 관찰
- 구분하려는 두 설명
- 다음 최소 확인 행동
- 성공 또는 반증 조건

강한 차이나 연결 가능한 값이 없으면 미실행 공개 표면을 탐색한다. 실제 응답 차이, 세션 차이, 소비할 정확한 값 또는 미검증 상태 변화가 생기면 해당 흐름을 짧게 검증한다. 연속 두 번의 확인에서 새 차이, 새 값 또는 새 상태 변화가 없으면 가설을 보류한다. 새로운 관찰이 생기기 전에는 같은 가설을 다시 열지 않는다.

이는 취약점별 공격 규칙이 아니라 탐색 정체와 무제한 집중을 막는 공통 실행 계약이다.

## 6. 한 번의 개발 반복

한 번의 반복은 취약점 네 개를 각 한 번 실행하는 것으로 제한한다.

초기 개발 표본은 다음과 같다.

| 표본 | 역할 |
|---|---|
| 경로 순회 보고서 다운로드 | v10과 v11에서 성공한 회귀 감시 대조군 |
| 비밀번호 재설정 바꿔치기 | v10 성공, v11 실패인 인증과 세션 회귀 사례 |
| 상점 간 환불 연쇄 | v11에서 성공한 업무 절차 사례와 주문 편향 확인 |
| 상품 검색 SQL 주입 | 두 버전에서 실패한 입력 해석 사례 |

이 표본의 취약점 이름, 경로, 페이로드와 정답은 공격자 코드와 프롬프트에 넣지 않는다.

반복 순서는 다음과 같다.

1. 전략 변경 완료
2. 구조 검사와 경로 및 필드명 변형 검사
3. 네 표본을 같은 고정 조건으로 각 한 번 실행
4. 실행 프로세스와 완료 산출물을 직접 확인
5. 성공, 요청 수, 모델 호출 수, 시간과 종료 상태 비교
6. 요청 흐름, 가설 전환, 반복 행동, 미사용 값과 미검증 상태 변화 분석
7. 두 사례 이상에서 확인된 공통 원인만 수정
8. 같은 네 표본을 같은 조건으로 다시 각 한 번 실행
9. 결과 보고 후 다음 반복 여부 결정

예약 작업을 등록했다는 이유로 실행을 완료한 것으로 보지 않는다. 실행 중에는 프로세스, 체크포인트와 완료 파일을 직접 확인한다.

## 7. 편향 방지 규칙

- 특정 엔드포인트 문자열 추가 금지
- 취약점 이름과 시나리오 ID 검사 금지
- 정답 페이로드와 정답 순서 추가 금지
- 문제별 조건문과 예외 목록 추가 금지
- 실패한 문제를 평가에서 제외하는 행위 금지
- 같은 문제를 성공할 때까지 반복한 결과만 성공률로 사용하는 행위 금지
- 한 사례에서만 나타난 현상을 공통 코드 규칙으로 승격하는 행위 금지
- 개발 표본에서 성공해도 별도 미사용 표본 검증 전 범용 개선 선언 금지

경로와 필드명을 바꾼 변형에서도 판단 흐름이 유지되는지 확인한다. 변형 실패를 원래 이름의 동의어 목록 추가로 해결하지 않는다.

## 8. 확대 조건

네 개 개발 표본을 통과한 사실만으로 24개 전체 실행을 승인하지 않는다. 다음 조건을 모두 확인해야 한다.

- 기존 성공 대조군의 회귀 없음
- 기존 실패 또는 회귀 사례 최소 한 개 개선
- 성공 시험의 요청 수와 모델 호출 수 중앙값이 기준보다 20% 이상 악화되지 않음
- 출력 계약 오류, 격리 위반과 금지 도구 사용 0건
- 개발에 사용하지 않은 별도 네 개 표본에서 성능 유지
- 경로명과 필드명 변형에서 성능과 행동 흐름 유지
- 실행 프로필 ID, 안내문 해시와 전략 코드 해시가 사전 기록과 일치

이후에도 전체 24개 실행은 한 번에 개발과 수정을 섞지 않는다. 실행 중 소스 변경을 금지하고 완료 후 결과를 분석한다.

## 9. 보고 규칙

각 반복 보고에는 다음을 포함한다.

- 실제 실행한 버전과 해시
- 네 표본별 성공 여부와 난이도
- 요청 수, 모델 호출 수, 시간과 종료 상태
- 성공 또는 실패의 직접 원인
- 이상 집중과 넓은 탐색 부족 여부
- 모델이 사용한 공개 단서와 사용하지 않은 공개 단서
- 코드 변경이 특정 문제 규칙인지 공통 실행 계약인지에 대한 감사 결과
- 실행하지 않은 검사와 남은 한계

구조 검사를 통과했다는 사실을 공격 성능 개선으로 표현하지 않는다. 실제 시험을 실행하지 않았다면 성능은 미검증이라고 기록한다.
