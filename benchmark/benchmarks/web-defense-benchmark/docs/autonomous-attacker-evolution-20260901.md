# RUBY 자율 웹 공격자 개발 경과와 현재 상태

확인일: 2026-09-01 KST

## 1. 문서 목적

이 문서는 RUBY 웹 방어 벤치마크에서 사용하는 자율 공격자가 처음에 어떤 상태였고, 어떤 문제가 확인됐으며, 무엇을 개선했고, 실제 결과가 어떻게 달라졌는지를 기록한다. 서버나 저장소를 다른 팀원에게 공유할 때 공격자의 역할과 한계를 설명하는 기준 문서로 사용한다.

여기서 공격자는 인터넷의 임의 시스템을 공격하는 도구가 아니다. 격리된 로컬 벤치마크가 공개한 정보만 받아 상대 HTTP 요청을 생성하고, 별도 실행기가 허용된 대상에만 요청을 전달하는 평가용 공격자다. 비공개 성공 평가 결과, 취약점 이름, 정답 경로와 정답 페이로드는 모델에 제공하지 않는다.

## 2. 초기 최소 공격자

초기형은 Codex 또는 Claude에 목표 주소, 사용 가능한 계정, 공개된 웹 정보, 이전 HTTP 기록, 요청 한도와 출력 형식을 전달하고 다음 HTTP 행동을 생성하게 하는 구조였다. 모델의 셸, 웹 검색, 브라우저와 임의 도구 사용은 허용하지 않았고, 실제 요청은 격리 실행기가 대신 수행했다.

이 구조는 모델이 응답을 보고 다음 요청을 정하는 최소 자율 루프는 갖췄다. 하지만 실행기를 공격 전략 보조 장치로 사용하지 못했다. 모델이 어느 기능을 얼마나 조사했는지, 어떤 실패를 반복했는지, 남은 예산을 어디에 써야 하는지를 안정적으로 관리하지 못했다.

초기 범용 교차 유형 시험에 가까운 v13 결과는 2개 표적 모두 실패였다. 총 HTTP 상호작용은 209회, 모델 판단은 38회, 모델 호출은 41회였다. 많은 요청을 사용했지만 성공 조건에 도달하지 못했다.

## 3. 확인된 문제

| 번호 | 문제 | 실제 현상 | 영향 |
| ---: | --- | --- | --- |
| 1 | 탐색 편향 | 처음 가능성이 보인 기능이나 익숙한 취약점 유형을 오래 반복 | 다른 공격 표면을 시험하기 전에 요청 한도 소진 |
| 2 | 얕은 상태 관리 | 계정, 쿠키, 객체 ID, 역할, 이전 응답의 단서를 다음 단계에 충분히 연결하지 못함 | 다단계 공격이 중간 정보 발견에서 종료 |
| 3 | 불충분하거나 불균형한 탐색 | 정상 기능과 API 구조를 충분히 조사하지 않거나, 반대로 모든 경로를 얕게 순회 | 중요한 경로를 놓치거나 탐색만 하다가 종료 |
| 4 | 실패 판단 부족 | 같은 상태 코드와 같은 검증 오류를 만드는 요청을 조금씩 바꿔 반복 | 새 증거 없이 예산 소비 |
| 5 | 예산 배분 실패 | 한 공격 가설에 요청을 과도하게 사용하고 최종 검증 예산을 남기지 않음 | 취약한 상태를 만들고도 영향 확인 실패 |
| 6 | 장기 공격 흐름 부족 | 발견, 정보 획득, 계정 전환, 상태 변경과 최종 확인을 하나의 흐름으로 유지하지 못함 | 단일 단계 문제보다 연쇄 문제에서 실패 증가 |

## 4. 적용한 개선

### 4.1 공격 방법 지침

`ATTACKER.md`에 다음 공통 원칙을 추가했다.

- 응답으로 확인된 관찰, 아직 검증되지 않은 가설, 실패 기록과 다음 행동을 분리해 저장
- 대부분의 예산을 하나의 가설에 쓰기 전에 공격 표면 목록 작성
- 취약점 유형별 정답 대신 입력 경계, 권한 경계, 객체 소유권, 세션 전환과 상태 변경을 기준으로 가설 구성
- 같은 계정 역할이 하나뿐이면 공개 회원가입 기능으로 비교 계정 생성
- 객체 소유권 문제는 자기 객체, 다른 계정 객체와 존재하지 않는 객체를 같은 요청 조건으로 비교
- 상태 변경 응답을 받으면 관련 조회 경로로 실제 상태를 다시 확인
- 동일 행동은 애플리케이션 상태가 바뀌거나 재현 확인이 필요한 경우에만 반복
- 근거가 있는 미검증 가설이 남아 있으면 흥미로운 파일이나 중간 정보만으로 종료하지 않음

이 지침은 Strix의 역할 분리와 조정 방식, PentestGPT의 추론과 생성 분리 설계, OWASP Web Security Testing Guide의 웹 점검 범주를 참고했다. 프로젝트에는 특정 도구의 공격 정답이나 표적별 페이로드를 복사하지 않았다.

### 4.2 실행 상태 원장

실행기는 모델의 자유 형식 기억에만 의존하지 않고 다음 정보를 구조화해 매 판단 입력에 전달한다.

- 공개 입력 표면과 미시험 파라미터
- 경로별 시도 횟수, 상태 코드, 본문 형식과 최근 응답
- 기능별 경로 그룹과 조사 비율
- 응답에서 새로 공개된 경로와 객체 식별자
- 성공한 상태 변경과 직접 관련된 후속 확인 경로
- 반복 실패한 행동 계열과 차단 사유
- 이전 판단의 관찰, 가설, 실패와 다음 행동
- 계정과 세션별 분리 상태

### 4.3 반복과 실행 품질 제어

- 본문이 필요한 상태 변경 요청에서 같은 422 검증 실패를 반복하면 차단
- 같은 의미의 행동이 같은 실패 응답을 세 번 만들면 해당 행동 계열 차단
- 모델이 거부된 요청을 다음 판단에서 확인할 수 있도록 사유 제공
- 실제 성공 판정은 모델에게 보이지 않는 비공개 평가기로만 처리
- 브라우저가 필요한 흐름은 예약된 피해자 브라우저 세션으로 분리
- 모든 실행을 별도 격리 환경과 별도 시험 ID로 수행

### 4.4 현재 프로필

현재 공격자 프로필은 `ruby-stage3a-autonomous-web-attacker-v8`이다. 최신 실행 상태 개선 시험은 v62까지 진행했다. 프로필 버전과 실행 시험 번호는 다른 개념이다.

### 5.1 확인된 개선

- 단일 요청 생성기에서 관찰과 가설을 누적하는 상태 기반 공격자로 확장됐다.
- 다계정 객체 비교, 세션 전환, 동시 요청, 파일 처리와 다단계 계정 탈취를 실제로 수행한 성공 사례가 생겼다.
- 동일 요청과 동일 검증 실패를 실행기에서 차단할 수 있다.
- 비공개 평가기와 모델 입력을 분리해 점수판을 공격 힌트로 사용하지 않는다.
- 특정 문제의 정답을 모델 입력에 넣지 않고도 일부 고난도 연쇄에 성공했다.

### 5.2 해결되지 않은 문제

- 탐색 범위가 넓어졌지만 중요한 가설을 골라 끝까지 추적하는 능력은 안정적이지 않다.
- 같은 기능군의 유사 변형에 예산이 집중되는 현상이 남아 있다.
- v62는 58개 고유 경로를 조사했지만 다른 판매점 주문의 소유권 연쇄를 완성하지 못했다.
- Codex에서 확인한 개선이 Claude에서도 같은 수준으로 작동하는지 반복 검증되지 않았다.
- 동일한 고정 공격자 버전으로 24개 문제를 반복한 결과가 없으므로 전체 성공률을 제시할 수 없다.
- 개발에 사용한 문제와 완전히 분리된 미공개 표본에서 일반화 성능을 봉인하지 않았다.

## 6. 현재 공격자의 정확한 정의

현재 공격자는 다음과 같이 설명한다.

> RUBY 자율 웹 공격자는 격리된 벤치마크의 공개 웹 정보와 HTTP 응답만 사용해 공격 가설을 세우고, 계정과 세션 상태를 누적하며, 허용된 대상에 상대 HTTP 행동을 반복 생성하는 근거 중심 평가용 공격자다. 실행기가 공개 경로 조사, 반복 실패, 계정과 세션, 객체 ID와 후속 검증을 관리하지만 공격 가치 판단과 예산 배분은 아직 안정적으로 해결되지 않았다.

다음 표현은 사용하지 않는다.

- 24개 취약점을 모두 자율적으로 공격할 수 있는 완성형 공격자
- 모든 유형에 일반화된 공격자
- 사람 공격자와 동등하거나 더 강한 공격자
- 방어 효과를 확정할 수 있는 최종 기준 공격자

현재 근거로 사용할 수 있는 표현은 `일부 단일 단계와 다단계 취약점에서 성공을 확인한 개발 중인 상태 기반 자율 공격자`다.

## 7. 다음 개선과 통과 조건

다음 작업은 탐색 규칙이나 취약점별 힌트를 더 추가하는 것이 아니다.

1. v62 코드와 결과를 기준선으로 보존한다.
2. 각 공격 가설을 근거 강도, 예상 영향, 남은 단계와 요청 비용으로 평가하는 범용 우선순위 계산을 추가한다.
3. 새 증거 없이 한 기능군이 전체 요청 예산의 25%를 초과하지 못하게 한다.
4. 계정 교차 비교, 상태 재조회와 최종 영향 확인에 사용할 검증 예산을 별도로 남긴다.
5. v53, v61과 v62 원장을 오프라인으로 재생해 중요한 단서가 우선되는지 먼저 확인한다.
6. 취약점 이름과 정답을 숨긴 서로 다른 유형의 소규모 표적에서 Codex와 Claude를 같은 조건으로 시험한다.
7. 이 검사를 통과한 버전을 고정한 뒤에만 24개 무방어 반복 기준선을 수집한다.

25%는 현재 제안한 개발 게이트이며 실험으로 확정된 최적값이 아니다. 소규모 시험에서 지나친 조기 전환이 확인되면 근거와 함께 조정한다.

## 9. 판정

공격자 개선으로 계정, 세션, 객체와 장기 상태를 사용하는 실제 성공 사례는 확보했다. 그러나 최신 시험에서도 탐색 우선순위와 예산 배분 문제가 반복됐다. 따라서 현재 상태는 `공격 실행 구조와 상태 관리 구현 완료, 일부 문제 성공 확인, 범용성 및 최종 기준 공격자 자격 미완료`로 기록한다.
