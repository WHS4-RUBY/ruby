# 멘토 피드백 반영 상태

확인일: 2026-09-11 KST

## 결론

현재 저장소에서 확인되는 탐지 컴포넌트와 `static-guard`에는 XSS 또는 CSRF 공격 탐지 기능이 없다. 취약점 웹의 비공개 평가기는 준비된 일부 시나리오에서 브라우저 코드 실행이나 서버 상태 변경을 확인할 수 있지만, 이것은 공격 탐지가 아니라 실험 성공 판정이다.

XSS와 CSRF 시나리오는 34개 취약점 포트폴리오에서 삭제하지 않는다. 다만 RUBY 탐지 또는 방어 구현과 오탐 검증이 끝나기 전에는 해당 시나리오를 요청 기반 방어 효과 집계에 넣지 않는다.

## 서로 다른 세 가지 판정

| 구분 | 질문 | 현재 지원 |
| --- | --- | --- |
| 공격자 식별 | 요청을 보낸 사용자가 공격자인가 | 평가 대상 아님 |
| 공격 요청 탐지 | 관측한 요청이 XSS 또는 CSRF 공격인가 | 현재 구현 근거 없음 |
| 공격 성공 판정 | 브라우저 코드 실행이나 보호 상태 변경이 실제로 일어났는가 | 준비된 일부 시나리오에서 지원 |

멘토가 질문한 탐지는 두 번째 항목이다. 취약점 웹의 비공개 평가기가 담당하는 것은 세 번째 항목이다.

## XSS 판정

| 유형 | 취약점 재현과 성공 판정 | 요청 기반 탐지 | 방어 효과 집계 |
| --- | --- | --- | --- |
| 반사형 XSS | 전용 시나리오 없음 | 회의에서 탐지팀의 가능 설명이 있었지만 현재 원격 저장소에서 구현과 변형 페이로드 결과를 확인하지 못함 | 구현과 검증 전 제외 |
| 저장형 XSS | 합성 파생 모듈과 원본 Roundcube 쌍에서 준비된 브라우저 동작을 판정 | 현재 탐지기와 `static-guard`에 구현되지 않음 | 구현과 오탐 검증 전 제외 |
| DOM 기반 XSS | 전용 시나리오와 브라우저 계측 없음 | 서버에 전달되지 않는 값은 현재 요청 기반 탐지기로 관측할 수 없음 | 현재 범위에서 제외하고 제한으로 기록 |

합성 브라우저 모듈의 애플리케이션 콜백 사건은 피해자 세션, 소유자와 요청 형태를 묶은 간접 증거다. Playwright가 확인하는 브라우저 표식과 같은 직접 계측으로 표현하지 않는다. 원본 Roundcube 쌍의 Playwright 표식 검사는 이 콜백과 별도다.

## CSRF 판정

`cross-site-request-forgery.support-role-change`는 CSRF 방어가 빠진 취약판과 방어가 적용된 안전판, 역할 변경이라는 성공 상태를 시험한다. 그러나 현재 탐지 컴포넌트가 정상 사용자의 요청과 외부 사이트가 유도한 요청을 안정적으로 구별한다는 근거는 없다.

CSRF는 다음 두 결과를 분리한다.

1. 안전판의 토큰 또는 출처 검증이 상태 변경을 막는가
2. 별도 RUBY 방어가 공격을 차단하면서 정상 상태 변경 요청을 보존하는가

첫 번째는 취약점 쌍의 기능 검사다. 두 번째가 완료되기 전에는 CSRF를 동적 방어 효과 집계에 넣지 않는다.

## 실험 편입 조건

XSS 또는 CSRF를 방어 효과 집계에 넣으려면 다음 근거가 모두 있어야 한다.

1. 취약판에서 기준 공격 성공
2. 안전판에서 동일 공격 실패
3. 비공개 평가기의 실제 효과 판정
4. RUBY 탐지 또는 방어를 통한 공격 차단
5. 정상 요청과 정상 HTML 입력에 대한 오탐 검사
6. 원시 결과, 실행 설정과 재현 가능한 해시 보존

조건을 만족하지 못한 시나리오는 포트폴리오에는 남기되 상태를 `방어 평가 준비 미완료`로 표시한다.

## 모델 식별 재검증

2026년 9월 11일 설치된 Codex CLI 0.154.0을 `--json`으로 직접 실행했다. 출력에는 스레드 ID, 응답과 토큰 사용량은 있었지만 모델 ID는 없었다. 기존 실행기는 명령행의 요청값 `gpt-5.6-sol`을 `observed_model_id`로 그대로 저장했다. 이는 관측 증거가 아니다.

실행기는 이제 요청 모델, 응답에서 관측한 모델, 식별 근거와 검증 여부를 따로 기록한다. 응답에 모델 ID가 없으면 관측값은 비우고 확증 분석의 무결성 검사를 실패시킨다. 기존 5회와 99회 실행의 성공 횟수는 삭제하지 않지만, 모델 동일성이 검증된 방어 효과 주장에는 사용하지 않는다.

통계 분석도 독립 검토 전에 효과 주장을 허용하지 않도록 바꿨다. 분석기는 통계 관문 통과 여부만 기록하고 `positive_effect_claim_allowed`는 `false`로 둔다. 구현 비참여자의 검토 기록과 입력 해시를 검증한 별도 결과만 최종 효과 주장을 허용한다.

## 아직 완료되지 않은 검증

- 탐지팀이 회의에서 설명한 반사형 XSS 구현의 브랜치와 커밋 확인
- 저장형 XSS 변형 페이로드와 정상 HTML 오탐 시험
- CSRF 정상 요청과 공격 유도 요청의 방어 비교
- 구현에 참여하지 않은 팀원의 독립 실행
- 현재 HEAD에서 34개 전체 원시 pair 결과 재생성 및 보존
