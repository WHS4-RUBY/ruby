# 최신 팀 파이프라인 실제 연결 확인

확인일: 2026-09-23 KST

## 결론

최신 Detection, Defense와 자체 취약점 웹을 별도 로컬 Docker 환경에서 실제로 연결했다. 정상 요청 전달, 자동화 특징 점수, 정책의 지연 지시, Defense의 실제 지연 실행과 웹 응답을 확인했다.

**PR 제출 준비 완료로 판단하지 않는다.** 시험 요청이 들어가는 Detection 진입점에서 운영용 세션 조회 API도 인증 없이 응답했다. 공격자에게 식별 점수와 관측 기록을 숨겨야 하는 실험 조건에 맞지 않는다.

후속 제출 결정: 2026-09-23 사용자 승인에 따라 변경사항은 검토용 Draft PR로 제출한다. 위 결론과 원본 실행 기록의 `pr_ready=false`는 검사 당시 판정으로 보존한다. PR 검토 요청은 공개 실험 환경의 준비 완료를 의미하지 않으며, 운영 API 접근 경계는 별도 이슈로 전달한다.

이 결과는 팀 서버의 실제 노출 상태를 확인한 결과가 아니다. 서버 앞단에 별도 접근 제어가 있는지는 이번 검사에서 확인하지 않았다.

## 실행 범위와 근거

- 실제 실행 코드: `785753e13bb339a3ba0a709ff661126e2bff0f3b`.
- 실행 시각: 2026-09-23 02:15:45부터 02:16:35 KST.
- [정제한 실행 기록](../evidence/20260923/team-pipeline-runtime.json)에 원본 정책 설정, 시험 설정, 소스 파일 해시와 이미지 ID를 함께 보존했다.
- [실행 도구](../scripts/check_team_pipeline_runtime.py)는 기존 생산용 Compose로 8개 웹 서비스를 만들고 최신 Detection과 Defense 이미지를 연결한다.
- [Defense 관측 도구](../app/tools/team_pipeline_observer.py)는 실제 지연 함수를 그대로 호출한 뒤 경과 시간을 기록한다. 점수, 정책, 응답과 방어 실행 결과를 대체하지 않는다.
- 기존 로컬 스택과 분리된 이름, 네트워크, 볼륨 및 임시 loopback 포트를 사용했다. 완료 후 시험 컨테이너, 볼륨과 네트워크를 정리했다. 빌드 이미지는 로컬 캐시에 남는다.
- 취약 모듈을 켜지 않았고, 실제 익스플로잇이나 자율 공격 에이전트를 실행하지 않았다.

## 이번에 확인하지 않은 것

- 공격 요청 전반의 식별 정확도, 정상 입력 전체의 오탐률
- 29개 본 실험 대상 전체에서 방어 효과가 나타나는지
- 무방어와 방어 조건의 실제 공격 성공률 비교
- 팀 서버에서 최신 스택을 실행한 왕복 결과
- 비활성 전략 또는 앞으로 추가할 방어 모듈의 동작

현재 정책은 지연을 선택한다. 해당 지연의 실제 실행을 확인했으나 이를 공격 실행 차단이라고 부르지 않는다. 자동화 플래그 true와 공격 플래그 true도 구분한다.

## 수정 및 재확인할 지점

Detection 운영 경로와 실험 요청 경로를 분리하거나 운영 요청에 인증을 적용해야 한다. 공개 경로에는 웹 요청과 필요한 정적 telemetry 자원만 남기고, 점수, 세션, 설정 변경 등의 운영 기능은 운영자 경로로 제한하는 방식으로 검토한다.

요청 식별 로직 리팩터링은 환경구축 담당 범위라는 기존 결정에 따라 이번 작업에서는 Detection 구현을 임의로 바꾸지 않았다. 접근 경계가 수정되면 다음 두 조건을 확인해야 한다.

1. 시험 요청자에게 운영 정보와 변경 기능이 노출되지 않는다.
2. 정상 웹 요청, telemetry 수집, 기존 점수 기록과 방어 지시 적용은 유지된다.

## 시험 도구 수정 이력

첫 실행은 HTTP 검사 전에 Python 이름 충돌로 중단됐다. 충돌을 수정했고 생성한 자원은 정리했다.

두 번째 실행에서는 무해한 표지를 ssti로 기록해야 한다고 잘못 가정한 검사가 실패했다. 실제 CRS는 rce로 기록했다. 표지를 특정 공격 범주의 정답으로 취급하는 검사를 제거하고, 실제 엔진 결과가 연결 경로를 거쳐 기록되는지 확인하도록 고쳤다. 앞선 실패를 원본 기록에서 삭제하지 않았다.

세 번째 실행은 수정된 계약 검사 13개를 통과했다. 운영 정보 노출은 그대로 확인되어 준비 상태를 보류했다.
