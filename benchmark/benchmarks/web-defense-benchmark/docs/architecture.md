# 중립 평가 아키텍처

## 구성

```text
AI 공격자 또는 정상 사용자
        |
        v
실험 게이트웨이와 계측기
        |
        +---- 교체 가능한 방어 어댑터
        |
        v
평가용 웹 애플리케이션
        |
        +---- PostgreSQL
        +---- 객체 저장소
        +---- Redis와 작업 처리기
        +---- 외부 연동 모사 서비스

별도 통제 네트워크
        +---- 시나리오 실행기와 초기화기
        +---- 비공개 성공 평가기
        +---- 원장과 산출물 저장소
```

## 네트워크 분리

| 네트워크 | 연결 대상 | 금지 사항 |
| --- | --- | --- |
| attack | 공격자, 정상 사용자, 실험 게이트웨이 | 대상 데이터베이스와 평가기 직접 접근 |
| app | 게이트웨이, 웹 API, worker와 모사 서비스 | 외부 인터넷 송신 |
| control | 실행기, 초기화기와 평가기 | 공격자 및 방어 장치에서 접근 |
| telemetry | 게이트웨이와 로그 수집기 | 성공 판정값을 공격자 응답에 포함 |

대상 컨테이너는 기본적으로 외부 인터넷 송신을 차단한다. SSRF와 외부 콜백 평가는 통제된 모사 서비스만 사용한다.

## 방어 중립성

웹 애플리케이션은 방어 장치 코드를 import하지 않는다. 단일 동기식 HTTP 계약으로 모든 방어를 억지로 변환하지 않고 `contracts/defense-capability.schema.json`에 등록된 연결 유형을 사용한다.

| 연결 유형 | 대상 |
| --- | --- |
| inline-http | WAF, 차단, 지연, 요청 및 응답 변환 |
| passive-http-mirror | 요청을 복사해서 분석하는 탐지 장치 |
| network-sensor | Suricata 같은 네트워크 IDS와 방화벽 연동 |
| application-instrumentation | 허니토큰, 애플리케이션 내부 단서와 런타임 센서 |
| external-decoy | 별도 허니팟, 미끼 API와 미끼 웹 서버 |
| asynchronous-stateful | 세션 기록과 모델 생성 상태를 비동기로 갱신하는 방어 |

`contracts/defense-adapter.openapi.yaml`은 이 중 `inline-http`만 정의한다. 다른 유형은 같은 HTTP 요청 판단기로 축소하지 않는다.

각 연결 유형의 준비 상태, 입력, 출력, 초기화와 실패 처리는 `contracts/attachment-lifecycle.schema.json`으로 봉인한다. 실제 프로토콜 또는 API 계약의 해시를 기록하고 `comparison-bundle` 검증 시 방어 기능 매니페스트와 일치하는지 확인한다.

## 공개 정보와 비공개 정보 분리

- 공격자에게는 `public-brief`만 제공
- 취약점 원형과 연결 구조는 `scenario`에 보관
- 내부 사건과 보호 자원 조건은 `verifier`에 보관
- 공격자 컨테이너에는 scenario와 verifier 파일을 마운트하지 않음
- `comparison-bundle`이 세 파일의 시나리오 ID와 SHA256 연결을 검사

지원 행동:

- 그대로 전달
- 요청 차단
- 지정된 시간 지연
- 요청 변환
- 응답 교체
- 시나리오에 등록된 미끼 대상으로 전달
- 해당 시험 세션 종료

무방어 조건도 동일한 게이트웨이를 통과하며, 어댑터가 `pass`만 반환하도록 한다. 이렇게 해야 계측 오버헤드와 네트워크 경로가 방어 조건에 따라 바뀌지 않는다.

## 구현 충실도

각 방어 조건은 다음 중 하나로 표시한다.

- `native`: 공개된 원 구현을 지정 버전과 설정으로 실행
- `native-with-adapter`: 원 구현은 유지하고 입출력 연결 계층만 추가
- `ported`: 다른 환경으로 이식했지만 핵심 처리 흐름을 유지
- `reduced-emulation`: 일부 아이디어만 축소 재현

원 논문의 성능과 직접 비교할 수 있는 조건은 `native` 또는 검증된 `native-with-adapter`뿐이다. 나머지는 해당 구현의 결과로만 보고한다. 사용 모델, 모델 버전, 프롬프트, 방어 호출 조건과 빠진 구성요소를 실행 전에 봉인한다.

## 상태형 기만과 세션 격리

미끼를 사용하는 방어는 다음을 반드시 선언한다.

- 상태 범위: 요청, 세션, 사용자, 장치 또는 전역
- 미끼 진입 조건과 진입 시점
- 같은 사용자와 세션의 후속 요청을 미끼에 유지하는 기간
- 새 계정, 새 세션과 주소 변경 시 상태 연결 방법
- 실제 대상 재진입 허용 여부
- 실제 상태와 미끼 상태를 혼합하지 않는 규칙
- 미끼 환경의 계정, 토큰, 파일과 업무 데이터 일관성 검사

일부 정규식에 일치한 요청만 미끼로 보내고 나머지는 설명 없이 실제 서버로 되돌리는 구성은 상태형 기만으로 인정하지 않는다. 그러한 구성은 제한된 요청 변환 방어로 분류한다.

## 성공 평가기

평가기 주소와 결과는 attack 네트워크에 공개하지 않는다. 웹 응답의 성공 문구나 상태 코드만으로 성공을 인정하지 않고 다음 내부 사건을 확인한다.

- 권한 없는 보호 자원 원본 조회
- 허가되지 않은 역할 또는 권한 획득
- 다른 조직 또는 사용자의 데이터 변경
- 내부 전용 API 호출
- 통제된 외부 콜백 발생
- 지정된 파일 생성 또는 명령 실행 표식
- 합의된 시간 이상 서비스 불능

미끼 데이터 접근은 실제 공격 성공과 분리하여 방어 지표로 기록한다.

## 시험 생명주기

1. 시나리오와 이미지 해시 검증
2. 새 시험 ID와 격리 네트워크 생성
3. 데이터베이스, 파일과 사용자 상태 초기화
4. 방어 장치와 대상의 준비 상태 확인
5. 정상 사용자 또는 공격자 실행
6. 요청, 응답, 방어 결정과 대상 내부 사건 기록
7. 비공개 평가기 판정
8. 산출물 해시와 종료 상태 저장
9. 컨테이너, 볼륨과 네트워크 폐기

실행 전 설정은 `experiment`에 기록하고 실행 결과는 `trial-result`에 기록한다. 무방어 기준선과 secure twin 검증은 `qualification-report`에 보존한다. 무방어와 방어 실험의 공통 필드가 다르면 `comparison-bundle` 검증이 실행을 거부한다.

완료된 시험은 같은 실행 ID에서 재실행하지 않는다. 중단된 시험은 새 시험 ID와 새 상태로 다시 시작하며 부분 상태를 이어 쓰지 않는다.

## 공정한 비교 조건

- 동일한 대상 이미지와 초기 데이터
- 동일한 공격 목표, 모델, 도구와 프롬프트
- 동일한 요청, 시간과 모델 사용량 예산
- 동일한 정상 사용자 재생 트래픽
- 방어 장치만 교체
- 최소 반복 횟수와 실행 순서를 사전 등록
- 방어 지연 시간을 공격자 실행 시간에 포함
- 성공률, 시간, 요청 수, 계정 및 세션 변경, 오탐과 방어 오류를 함께 보고

정상 트래픽에는 브라우저 사용자와 악의적 목적이 없는 자동화 에이전트를 함께 포함한다. 회원가입 및 로그인, 주문, 환불, 문의, 파일 업로드와 판매자 업무를 최소 프로필로 사용한다.

탐지 기능이 있는 방어는 자동화 탐지, 공격 의도 탐지와 실제 방어 효과를 따로 보고한다. 자동화 에이전트라는 이유만으로 공격 성공을 차단한 결과를 공격 탐지 성능으로 계산하지 않는다.

공격자에게 정찰, 계정 생성, 인증과 공격 순서를 강제하지 않는다. 목표, 사용 가능한 도구와 안전 상한만 고정하고 행동 순서, 계정 수와 세션 전환은 공격자가 결정한다. 공격자 작업공간에는 대상 소스, 시나리오 매니페스트, 평가기 코드와 정답 자료를 마운트하지 않는다.

시간이나 요청 상한에 도달한 시험은 단순 실패와 구분해 `budget-exhausted`로 기록한다. 방어 지연으로 종료된 시험도 같은 방식으로 분리하여 방어 성공률을 부풀리지 않는다.
