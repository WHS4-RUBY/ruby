# 탐지 작업 화면 설계

## 1. 방향
기존 Primer 계열 모니터링 UI를 유지한다. 주된 작업은 클라이언트 흐름을 고르고,
그 흐름의 요청을 훑고, 요청 하나를 열어 근거를 확인하는 것이다. 기술적인 집계
화면과 필터는 점진적 공개(progressive disclosure)로 계속 접근할 수 있게 둔다.
탐지 점수, 정책, 신원 판정 의미, API 계약은 바꾸지 않는다.

참고:
- https://docs.mitmproxy.org/stable/ — 흐름 목록과 선택한 요청 검사.
- https://www.zaproxy.org/docs/desktop/ui/ — 주 작업과 보조 상세의 분리.
- https://github.com/arkime/arkime — 검색 가능한 세션 조사.
- https://github.com/changeroa/StyleGallery/blob/main/patterns/split-sidebar/list-detail.md
  — 목록/상세의 공간 관계. 기존 스크롤 컨테이너에 맞춰 적용한다.

## 2. 색
`public/dashboard.html`의 기존 CSS 변수를 쓴다. 라이트/다크 쌍은 다음과 같다.
배경 `--bg`(#f6f8fa/#010409), 표면 `--surface`(#ffffff/#0d1117),
연한 표면 `--surface-muted`(#f6f8fa/#151b23),
테두리 `--border`(#d1d9e0/#30363d), 본문 `--text`(#1f2328/#e6edf3),
보조 본문 `--text-2`(#3d444d/#c9d1d9), 흐린 글자 `--muted`(#59636e/#9198a1),
링크·포커스 `--blue`(#0969da/#58a6ff), 공격 `--red`(#d1242f/#f85149),
경고 `--amber`(#9a6700/#d29922), 성공 `--green`(#1a7f37/#3fb950).
선택 상태는 강조색 테두리가 아니라 `--select-bg`와 중립 테두리로 표현한다.
기존 의미 태그·배지·메서드·JSON 팔레트는 그대로 유지한다.

## 3. 타이포그래피
`--font`(한국어 시스템/Pretendard 스택)와 `--mono`(시스템 고정폭)를 유지한다.
두 대시보드는 Pretendard Variable v1.3.9 공식 스타일시트를
https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable.css
에서 불러온다. 이 스타일시트는 두께 45–920과 `font-display: swap`을 선언한다.
제목·본문·컨트롤은 `--font`를, URL·식별자·요청 필드·JSON은 `--mono`를 쓴다.
외부 CDN을 쓸 수 없을 때는 기존 시스템 폰트 대체가 적용된다.
본문 14px, 주요 제목 16–20px, 보조 라벨 12–13px, 요약 수치 26px.
좁은 화면에서는 입력과 주요 콘텐츠를 16px로 둔다.
기술적인 경로는 행에서는 줄여 쓰고 펼친 상세에서는 줄바꿈한다.

## 4. 레이아웃과 여백
기존 4px 간격 리듬을 쓴다: 4, 8, 12, 16, 20, 24, 32, 48px.
요약은 서로 경쟁하는 카드 네 장이 아니라 하나의 간결한 띠로 둔다.
목록/상세는 데스크톱에서 320px 목록과 가변 폭 요청 창으로 두고, 1100px 아래에서는
세로로 쌓는다. 목록은 자기 스크롤을, 요청 로그도 자기 스크롤을 따로 가진다.
펼친 보조 자료는 문서 스크롤로 본다. 동적 뷰포트 단위를 쓴다.
펼친 기술 표는 자체 가로 스크롤을 가지며, 390px에서 주요 콘텐츠가 넘치면 안 된다.

## 5. 구성요소와 상태
- **내비게이션**: 주 조사 탭과 기술 화면용 공개 컨트롤. 선택된 탭의 의미, 건수,
  키보드로 조작 가능한 네이티브 컨트롤을 유지한다.
- **흐름 카드**: 관찰된 IP와 짧은 ID로 구별한다. 신원 배지와 공격 라벨은 기존
  의미를 유지한다. 점수와 근거는 보이되, 특정 사람을 확정했다거나 확률이라고
  주장하지 않는다.
- **공개 컨트롤**: 설정, 도움말, 연결 근거, 고급 로그 필터에 네이티브
  `details`/`summary`를 쓴다. 동적으로 바뀐 펼침 상태는 갱신 후에도 유지한다.
  적용 중인 고급 필터 수는 접혀 있어도 요약에 표시한다.
- **요청 행**: 최신순. 버튼을 누르면 필드 표와 원본 JSON을 펼친다. 갱신 시
  포커스, 펼친 행, 검색 커서 위치, 스크롤 기준점을 유지한다.
- **비어 있음·오류·로딩**: 어떤 기록이 없는지와 다음에 할 일을 설명한다.
- **버튼**: 기본, 호버, 선택 시 톤 변화, 보이는 키보드 포커스, 비활성.
- **전체 상세 모달**: 닫기 동작이 있는 고정 헤더, 스크롤되는 본문 한 영역,
  간결한 관찰 요약, 그다음 요청 행. 점수 계산, 누적 이력, 연결 근거, 원본 특성
  수치는 접힌 네이티브 공개 컨트롤 네 개에 보존한다. IP 관찰에는 탐지 점수를
  넣지 않는다. 현재 공격 점수와 과거 최고치를 구분한다. 기준 미만 점수는 안전
  선언이 아니다. 원본 JSON은 분석 공개 컨트롤에서 계속 볼 수 있게 둔다.
  관찰된 값은 모두 이스케이프한다. 좁은 화면에서는 본문 여백 16px, 넓은 화면
  에서는 20px, 기존 12/14/16px 글자 크기를 쓰고, 요약 칸 네 개는 두 개로 흐른다.
  열 때 닫기에 포커스를 두고, 키보드 포커스를 모달 안에 가두며, 닫을 때 연 지점
  으로 포커스를 되돌린다.

## 6. 상호작용
장식적인 애니메이션은 쓰지 않는다. 네이티브 공개 컨트롤의 즉각적인 반응과 기존
120–150ms 피드백을 유지한다. 동작 줄이기 설정에서는 선택적 전환을 없앤다.
검색과 필터링은 새로고침을 요구하지 않는다. 2초마다 일어나는 갱신이 펼친 영역을
닫거나 현재 입력 포커스를 빼앗으면 안 된다.

## 7. 접근성
검색 라벨은 눈에 보이게 둔다. `summary`는 네이티브 키보드 조작을 유지한다.
모바일 터치 대상은 최소 44px. 상태는 색 외에 글자로도 알린다.
이스케이프된 요청 내용, 인증, 복사·내보내기, 대시보드 간 요청 링크를 유지한다.

## 8. 범위와 검증
범위는 탐지 대시보드로 한정한다. detection과 defense에 있던 기존 변경은 보존한다.
추가 의존성은 넣지 않는다.
두 테마에서 데스크톱/모바일, 비어 있음/채워짐 상태, 선택, 검색, 고급 필터, 상세,
전체 화면 로그, 갱신 후 상태 유지를 확인한다.
브라우저 QA 픽스처는 합성 데이터이며, 배포된 프록시를 검증하지 않는다.
